  چطور برنامه‌ام را به این سرور وصل کنم؟
  (اپِ اندروید · برنامهٔ ویندوز · هر سایتی)
═══════════════════════════════════════════════════════════════════════════


  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │   ساده‌ترین راه — یک برنامهٔ ویندوزی:                             │
  │                                                                 │
  │       نصب-برنامه.bat   ←  نصبش کن (پوشه را خودت انتخاب می‌کنی)    │
  │                                                                 │
  │   بعد از نصب، از میان‌برِ روی دسکتاپ بازش کن.                     │
  │   مرورگر لازم نیست، پنجرهٔ سیاه هم ندارد. همه‌چیز آن‌جاست:         │
  │   آدرسِ سرور، تستِ ورود با کد، تنظیماتِ پیامک و جی‌میل،            │
  │   کدِ آمادهٔ اندروید/ویندوز/سایت، و به‌روزرسانیِ خودِ برنامه.       │
  │                                                                 │
  │   (اگر ویندوز نداری، همان صفحه در مرورگر هم هست:                 │
  │       http://localhost:4700/connect  )                          │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘


───────────────────────────────────────────────────────────────────────────
  ۱) آدرسِ سرور را در برنامه چه بگذارم؟
───────────────────────────────────────────────────────────────────────────

  سه حالت دارد. اشتباهِ همیشگی این‌جاست، پس دقت کن:

    الف) برنامه روی همین کامپیوتر است
         →  http://localhost:4700

    ب) گوشی یا کامپیوترِ دیگر، ولی روی همان وای‌فایِ خانه
         →  http://192.168.1.xx:4700
         (عددِ درست را همان پنجرهٔ سیاهِ سرور موقعِ بالا آمدن می‌نویسد)

    ج) از بیرونِ خانه — اینترنتِ همراه، خانهٔ کسِ دیگر، سایتِ روی هاست
         →  آدرسِ تونل که با https شروع می‌شود
         (در پنل، بخشِ «تونل» همان آدرس نوشته شده)


  ⚠️ چهار دلیلِ همیشگیِ «وصل نمی‌شود»:

     ۱. سایتِ شما https است ولی آدرسِ سرور را http گذاشته‌اید.
        مرورگر خودش جلویش را می‌گیرد. باید آدرسِ https تونل را بگذارید.

     ۲. اپِ اندروید و آدرسِ http (بدونِ s): اندروید از نسخهٔ ۹ به بعد
        جلویش را می‌گیرد. یا آدرسِ https تونل را بگذارید، یا در فایلِ
        AndroidManifest.xml این را اضافه کنید:
            android:usesCleartextTraffic="true"

     ۳. فایروالِ ویندوز پورت ۴۷۰۰ را بسته. بارِ اول که سرور بالا می‌آید
        ویندوز می‌پرسد — «Allow / اجازه» را بزنید.

     ۴. گوشی روی اینترنتِ همراه است، نه وای‌فایِ خانه. آن‌وقت آدرسِ
        192.168… هیچ‌وقت کار نمی‌کند؛ باید آدرسِ تونل باشد.

  در برنامهٔ ویندوزی، تبِ «آدرسِ سرور» همین سه آدرس را آماده و با دکمهٔ کپی
  به شما می‌دهد — لازم نیست خودتان دنبالشان بگردید.

  تستِ سریع: همان آدرس را در مرورگرِ همان دستگاه باز کنید و آخرش
  /health بگذارید. اگر متنی با ok:true دیدید، سرور در دسترس است و
  مشکل از خودِ برنامه است، نه از سرور.
      مثال:  http://192.168.1.20:4700/health


───────────────────────────────────────────────────────────────────────────
  ۲) ورود با شمارهٔ موبایل یا جی‌میل و کدِ شش‌رقمی
───────────────────────────────────────────────────────────────────────────

  سرور این کار را حالا خودش انجام می‌دهد. برنامهٔ شما فقط دو درخواست
  می‌فرستد — نه ثبت‌نام، نه رمز عبور، نه دیتابیسِ جدا:

  ── قدم ۱: کد را بفرست ──────────────────────────────────────────────

      POST  http://<آدرس سرور>/api/app/auth/request-code
      { "phone": "09121234567" }

      یا با ایمیل:
      { "email": "someone@gmail.com" }

      سرور یک کدِ شش‌رقمی می‌سازد و پیامک/ایمیل می‌کند.

  ── قدم ۲: کدی که کاربر تایپ کرده را بفرست ──────────────────────────

      POST  http://<آدرس سرور>/api/app/auth/verify-code
      { "phone": "09121234567", "code": "123456" }

      جواب:
      { "ok": true, "token": "eyJ...", "user": { ... } }

  ── قدم ۳: از این به بعد ────────────────────────────────────────────

      همان token را در هر درخواست بگذارید:

          Authorization: Bearer eyJ...

      و برای گرفتنِ مشخصاتِ کاربر:
          GET  http://<آدرس سرور>/api/app/me

  توکن ۳۰ روز اعتبار دارد؛ یعنی کاربر هر بار مجبور نیست دوباره وارد شود.

  نکته‌های ریز که خودش رعایت می‌کند:
    • ۰۹۱۲… با ارقامِ فارسی هم قبول می‌شود
    • 0912… و +98912… و 98912… همه یک حساب حساب می‌شوند
    • کد ۲ دقیقه اعتبار دارد و بعد از ۵ بار غلط زدن می‌سوزد
    • هر شماره در ساعت بیشتر از ۵ بار کد نمی‌گیرد (جلوی سوءاستفاده)
    • ثبت‌نام لازم نیست: اولین ورود، خودش حساب می‌سازد


───────────────────────────────────────────────────────────────────────────
  ۳) چند برنامه دارم؛ کاربرهایشان قاطی نمی‌شود؟
───────────────────────────────────────────────────────────────────────────

  نه. کافی است هر برنامه اسمِ خودش را هم بفرستد:

      { "phone": "09121234567", "app": "pump" }
      { "phone": "09121234567", "app": "shop" }

  این دو، دو کاربرِ کاملاً جدا هستند با توکن‌های جدا. اگر app نفرستید،
  همه در یک جا («main») می‌افتند.

  فهرستِ برنامه‌ها و کاربرانِ هر کدام از پنل دیده می‌شود:
      GET  /api/app-admin        (با حسابِ مدیرِ پنل)


───────────────────────────────────────────────────────────────────────────
  ۳.۵) کلیدِ اختصاصی و تنظیماتِ جدا برای هر برنامه
───────────────────────────────────────────────────────────────────────────

  در برنامهٔ ویندوزی، تبِ «برنامه‌ها و سایت‌ها»: هر برنامه یک ردیف دارد با

      شناسه       shop
      کلید        hlp_1a2b3c…
      متنِ پیامک   «کد فروشگاه: {code}»
      طولِ کد      ۵ یا ۶ رقم
      روشن/خاموش  یک برنامه را ببندید، بقیه کار کنند

  پایینِ همان تب، آدرس‌های API همان برنامه آماده است؛ دکمهٔ «کپیِ آدرس‌های API»
  را بزنید و بدهید به سازندهٔ آن برنامه.

  اگر تیکِ «بدونِ کلید کار نکند» را بزنید، از آن به بعد درخواست باید کلید هم
  داشته باشد:

      { "phone":"09121234567", "app":"shop", "key":"hlp_1a2b3c…" }

  (یا در هدر:  X-Api-Key: hlp_1a2b3c… )

  تا وقتی این تیک را نزده‌اید، همه‌چیز مثلِ قبل باز است.


───────────────────────────────────────────────────────────────────────────
  ۴) کاری کن کد واقعاً پیامک/ایمیل شود
───────────────────────────────────────────────────────────────────────────

  تا وقتی این را تنظیم نکنید، ورود کار می‌کند ولی کد جایی فرستاده
  نمی‌شود — به‌جایش در پنجرهٔ سیاهِ سرور و در «پنل ← لاگ‌ها» نوشته
  می‌شود. برای آزمایش خوب است، برای مشتری نه.

  فایل را باز کنید:   homelab-panel\server\.env
  (اگر نبود، از روی .env.example یکی بسازید)

  ── جی‌میل ───────────────────────────────────────────────────────────

      OTP_EMAIL_HOST=smtp.gmail.com
      OTP_EMAIL_PORT=465
      OTP_EMAIL_USER=your-address@gmail.com
      OTP_EMAIL_PASS=رمزِ ۱۶ حرفیِ App Password
      OTP_EMAIL_FROM=your-address@gmail.com

      ⚠️ رمزِ عادیِ جی‌میل کار نمی‌کند. باید:
         حسابِ گوگل ← Security ← «تأیید دومرحله‌ای» را روشن کنید
         بعد ← «App passwords» ← یک رمزِ ۱۶ حرفی بسازید
         همان رمز را این‌جا بگذارید (فاصله‌هایش را بردارید).

  ── پیامک ───────────────────────────────────────────────────────────

      OTP_SMS_PROVIDER=kavenegar
      OTP_SMS_KEY=کلیدی که پنلِ پیامک به شما داده
      OTP_SMS_TEMPLATE=نامِ قالبِ تأیید      (اگر ندارید خالی بگذارید)
      OTP_SMS_SENDER=شمارهٔ خطِ خودتان

      به‌جای kavenegar می‌شود smsir یا melipayamak یا ghasedak گذاشت.
      سرویسِ دیگری دارید؟ webhook بگذارید و آدرسش را بدهید —
      توضیحش در .env.example هست.

  آخرش سرور را ببندید و دوباره باز کنید. تمام.

  برای تستِ واقعی: صفحهٔ /connect را باز کنید، شمارهٔ خودتان را بزنید.
  اگر نرفت، متنِ دقیقِ خطا همان‌جا نوشته می‌شود (رمزِ اشتباه، اعتبارِ
  تمام‌شده، قالبِ نادرست و…).


───────────────────────────────────────────────────────────────────────────
  ۵) فهرستِ کاملِ آدرس‌ها
───────────────────────────────────────────────────────────────────────────

  برای برنامه‌ها (باز، بدونِ نیاز به حسابِ مدیر):

    GET   /health                          سرور بالاست؟
    GET   /connect                         صفحهٔ راهنما و تست
    GET   /api/app/config                  کدِ چند رقمی؟ پیامک روشن است؟
    GET   /api/app/ping                    تستِ سریعِ اتصال
    POST  /api/app/auth/request-code       فرستادنِ کد
    POST  /api/app/auth/verify-code        گرفتنِ توکن
    GET   /api/app/me                      مشخصاتِ کاربرِ واردشده
    PUT   /api/app/me                      عوض کردنِ نامِ کاربر
    POST  /api/app/auth/logout             خروج

  برای خودتان از پنل (با حسابِ مدیر):

    GET   /api/app-admin                   آمار و تنظیمات
    GET   /api/app-admin/users             فهرستِ کاربران
    POST  /api/app-admin/users/<id>/block  مسدود کردنِ یک کاربر
    POST  /api/app-admin/test              فرستادنِ یک کدِ آزمایشی
    PUT   /api/app-admin/settings          تغییرِ تنظیماتِ پیامک/ایمیل


───────────────────────────────────────────────────────────────────────────
  ۶) اگر باز هم نشد
───────────────────────────────────────────────────────────────────────────

  این جدول را از بالا به پایین برو:

    /health در مرورگرِ همان دستگاه باز نمی‌شود
        → مشکلِ شبکه است: آدرس، فایروال، یا وای‌فایِ متفاوت

    باز می‌شود ولی برنامه وصل نمی‌شود
        → آدرسِ داخلِ برنامه را نگاه کن؛ احتمالاً http/https قاطی شده

    کد نمی‌رسد
        → پنل ← لاگ‌ها. اگر آن‌جا نوشته «پیامک تنظیم نشده»، بخشِ ۴

    کد می‌رسد ولی «کد درست نیست»
        → کد ۲ دقیقه اعتبار دارد؛ کدِ جدید بگیر
