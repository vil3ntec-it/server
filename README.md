# سرورِ خانگیِ پمپ یعقوبی

نسخهٔ برنامه: **2.9.316** — نسخهٔ پنل: **1.2.0**

این مخزن دو بخش دارد که باید **کنارِ هم** بمانند؛ پنل، دستیار را از همین‌جا پیدا می‌کند:

| پوشه | چیست |
| --- | --- |
| `homelab-panel/` | پنلِ مدیریتِ سرورِ خانگی **و مرکز فرمان** (Express + Socket.IO + SQLite) به‌همراه رابط کاربریِ ساخته‌شده در `server/public` |
| `homelab-panel/desktop/` | برنامهٔ ویندوز (Electron) — پنل و ترمینال در یک پنجره |
| `homelab-panel/agent/` | Agent سبکِ سرور — روی VPS یا هر ماشینِ دیگر اجرا می‌شود و گزارشِ واقعی می‌فرستد |
| `ai-support/` | دستیارِ پشتیبانیِ هوشمند — فقط‌خواندنی، بدون وابستگیِ npm |
| `homelab-panel/desktop/` | برنامهٔ ویندوزیِ سرور و نصب‌کننده‌اش (روشن/خاموش، ترمینالِ داخلی، تنظیماتِ پیامک، به‌روزرسانی) |

## مرکز فرمان

پنل، علاوه بر مدیریتِ سرورِ خانگی، یک **مرکز فرمان** کامل هم دارد: پروژه‌ها،
سرورها (خانگی/VPS/ابری)، IP و پورت و Endpoint، دامنه و ساب‌دامین و تونل،
Cloudflare، کاربران و فروشگاه‌ها و اشتراک‌ها، بکاپ و بازگردانی، انتشارها،
پیکربندیِ مرکزیِ برنامه‌ها، گاوصندوقِ رمزها، پایش و هشدار، دفترِ رخدادها و
به‌روزرسانی از GitHub.

راهنمای کامل: [`homelab-panel/مرکز-فرمان.md`](homelab-panel/مرکز-فرمان.md)

هیچ داده‌ای ساختگی نیست: هر «آنلاین» یعنی برنامه واقعاً به آن آدرس وصل شده.

راهنمای گام‌به‌گامِ راه‌اندازی در فایل [`از-اینجا-شروع-کنید.txt`](از-اینجا-شروع-کنید.txt) است.
راهنمای گام‌به‌گامِ راه‌اندازی در فایل [`از-اینجا-شروع-کنید.txt`](از-اینجا-شروع-کنید.txt) است،
و راهنمای وصل کردنِ برنامه‌ها (اپِ اندروید، برنامهٔ ویندوز، سایت‌ها) در
[`اتصال-برنامه-ها.txt`](اتصال-برنامه-ها.txt).

## برنامهٔ ویندوز (ساده‌ترین راه)

یک برنامهٔ واقعیِ ویندوز با آیکن روی دسکتاپ، که پنل و **ترمینالِ سرور** هر دو
داخلِ خودش است — و **به نصبِ Node.js هم نیاز ندارد**.

از [Releases](https://github.com/vil3ntec-it/server/releases) فایل
`ControlCenter-Setup-<نسخه>.exe` را بگیر و اجرا کن. (اگر هنوز Release نیست،
از زبانهٔ **Actions** → «برنامه ویندوز» → **Artifacts** برش دار.) موقعِ نصب می‌پرسد **کجا
نصب شود**، و بارِ اولِ اجرا می‌پرسد **اطلاعات کجا ذخیره شود**.

راهنما: [`homelab-panel/desktop/README-fa.md`](homelab-panel/desktop/README-fa.md)

## راه‌اندازیِ سریع (بدونِ برنامهٔ ویندوز)

پیش‌نیاز: Node.js نسخهٔ ۲۲ به بالا

**ویندوز — ساده‌ترین راه:** روی **`نصب.bat`** (یا `install-windows.bat`) دوبار کلیک کن.

از **هر جایی** کار می‌کند — حتی از پوشهٔ Downloads. اگر برنامه را نداشته باشی
خودش از GitHub می‌گیردش؛ اگر Node.js نباشد خودش نصبش می‌کند؛ بعد وابستگی‌ها را
می‌گیرد، `.env` را می‌سازد، سلامتِ نصب را می‌سنجد، پنل را بالا می‌آورد و مرورگر
را باز می‌کند. اجرای دوباره چیزی را خراب نمی‌کند.

**لینوکس / مک:**

```bash
cd homelab-panel
chmod +x نصب.sh && ./نصب.sh
```

**ویندوز — با دستیارِ هوشمند:** روی `نصب-همه-چیز.bat` دوبار کلیک کن.
وابستگی‌ها، Ollama، مدلِ مناسبِ همان کامپیوتر و ایندکسِ دانش را خودش می‌گیرد و بعد پنل را بالا می‌آورد
(حدود ۳ گیگابایت دانلود، فقط بارِ اول). دفعه‌های بعد `homelab-panel\server\start-windows.bat`.

دفعه‌های بعد فقط `homelab-panel/server/start-linux.sh` یا `start-windows.bat`.

برای بررسیِ سلامتِ نصب بدونِ بالا آوردنِ پنل:

```bash
cd homelab-panel/server && npm run doctor
```

برای نصب یا به‌روزرسانیِ «مغز» به‌تنهایی: `bash ai-support/نصب-مغز.sh` (ویندوز: `نصب-مغز.bat`).

دستیار خودش با پنل بالا می‌آید (پورت محلیِ 8788) و سایت از راهِ `/ai/support` به آن می‌رسد.
پنل روی پورت `4700` است؛ برای دیدنِ نسخهٔ در حالِ اجرا: `http://localhost:4700/health`

## به‌روزرسانی از GitHub

```bash
cd homelab-panel
./update.sh                  # لینوکس / مک
```

ویندوز: روی `homelab-panel\به‌روزرسانی.bat` دوبار کلیک کنید.

یا از خودِ پنل: **مرکز فرمان → به‌روزرسانی → بررسی به‌روزرسانی**.

پیش از نصب، از کلِ برنامه بکاپ گرفته می‌شود و پوشهٔ `data/` و فایل `.env`
هرگز دست نمی‌خورند. دکمهٔ «برگشت به نسخهٔ قبل» هم هست.
## برنامهٔ ویندوزی (بدونِ مرورگر)

روی **`نصب-برنامه.bat`** دوبار کلیک کنید — یک فایل است و کلِ برنامه داخلش:
نصب‌کننده باز می‌شود، پوشه را انتخاب می‌کنید، و برنامه با میان‌برِ دسکتاپ نصب
می‌شود. (ساختنِ همین فایل: `node tools/build-setup.mjs`) یک پنجرهٔ ویندوزیِ واقعی است
(WinForms — نه مرورگر، نه WebView، بدونِ هیچ نصبِ اضافه):

* روشن/خاموش کردنِ سرور و دیدنِ وضعیتش
* آدرسی که باید در اپ بگذارید (خانگی و اینترنتی) با دکمهٔ کپی
* تستِ ورود با کدِ شش‌رقمی، همان‌جا
* تنظیماتِ جی‌میل و سرویسِ پیامک (خودش در `.env` می‌نویسد و سرور را ری‌استارت می‌کند)
* کدِ آمادهٔ Kotlin / فلاتر / C# / جاوااسکریپت
* **ترمینالِ سرور داخلِ خودِ برنامه** — هیچ پنجرهٔ سیاهی باز نمی‌شود
* **دفترِ برنامه‌ها و سایت‌ها** — هر برنامه با شناسه، کلید و آدرسِ API خودش
* روشن/خاموش کردنِ **دستیارِ هوش مصنوعی** با یک تیک
* **به‌روزرسانی از داخلِ خودِ برنامه** — نسخهٔ تازه را از GitHub می‌گیرد، پشتیبان
  می‌گیرد و نصب می‌کند؛ پوشهٔ `data` و فایل `.env` دست نمی‌خورند

اگر پنجره باز نشد یا باز شد و بی‌صدا بسته شد، `اگر-باز-نشد.bat` را بزنید:
همان کار را با پنجرهٔ باز انجام می‌دهد و خطا را نشان می‌دهد. خطاها در
`homelab-panel/server/data/desktop-error.log` هم نوشته می‌شوند.

راهنما: [`homelab-panel/desktop/README-fa.md`](homelab-panel/desktop/README-fa.md)

## وصل کردنِ برنامه‌ها (اندروید / ویندوز / سایت)

سرور را روشن کنید و این آدرس را باز کنید:

```
http://localhost:4700/connect
```

آن صفحه سه چیز می‌دهد: آدرسی که باید در برنامه بگذارید، دکمهٔ تستِ زندهٔ
«ورود با کدِ شش‌رقمی»، و کدِ آمادهٔ اندروید/فلاتر/ویندوز/جاوااسکریپت.

ورودِ کاربرانِ برنامه‌ها با شمارهٔ موبایل یا ایمیل و کدِ شش‌رقمی انجام می‌شود —
بدونِ ثبت‌نام و بدونِ رمز عبور:

```
POST /api/app/auth/request-code   {"phone":"09121234567"}   # یا {"email":"a@gmail.com"}
POST /api/app/auth/verify-code    {"phone":"09121234567","code":"123456"}
→ {"ok":true,"token":"…"}          # بعد از این:  Authorization: Bearer <token>
```

برای این‌که کد واقعاً پیامک/ایمیل شود، در `homelab-panel/server/.env` سرویسِ
پیامک یا SMTP (جی‌میل) را بگذارید — نمونه‌ها در `.env.example` هستند. تا وقتی
تنظیم نشده، سرور کد را در «پنل ← لاگ‌ها» می‌نویسد تا بتوانید تست کنید.

راهنمای کاملِ فارسی: [`اتصال-برنامه-ها.txt`](اتصال-برنامه-ها.txt)

## هر برنامه، آدرس و کلیدِ خودش

هر اپ یا سایتی که وصل می‌شود یک شناسه دارد (`app`)، و می‌تواند کلیدِ اختصاصی،
متنِ پیامکِ جدا و طولِ کدِ جدا داشته باشد:

```bash
curl -X POST http://<سرور>/api/app/auth/request-code \
  -H "Content-Type: application/json" \
  -d '{"phone":"09121234567","app":"shop","key":"hlp_…"}'
```

مدیریتش از تبِ «برنامه‌ها و سایت‌ها» در برنامهٔ ویندوزی، یا از این مسیرها
(با حسابِ مدیرِ پنل، یا با کلیدِ محلیِ `data/local-admin.key`):

```
GET    /api/app-admin/clients            فهرست + آمارِ هر برنامه
POST   /api/app-admin/clients            ساختنِ برنامهٔ تازه
PUT    /api/app-admin/clients/<شناسه>     نام، کلیدِ اجباری، روشن/خاموش، متنِ پیامک
POST   /api/app-admin/clients/<شناسه>/key کلیدِ تازه
DELETE /api/app-admin/clients/<شناسه>     حذف
```

برنامه‌ای که بدونِ ثبتِ قبلی کد بخواهد، خودش ثبت می‌شود؛ تا وقتی «کلید اجباری»
را روشن نکنید همه‌چیز مثلِ قبل باز است.

## زیرساخت

پنل یک **زیرساختِ مرکزی** است، نه یک بک‌اندِ جدا برای هر برنامه. همهٔ
کلاینت‌ها (موبایل، دسکتاپ، وب) فقط یک آدرس می‌شناسند:

```
https://api.YOURDOMAIN.com/api/v1
```

IP سرور، پورت، و اینکه پشتِ تونل است یا reverse proxy — هیچ‌کدام به کلاینت
مربوط نیست. مهاجرتِ سرور به VPS یعنی یک تغییرِ DNS، نه انتشارِ دوبارهٔ اپ‌ها.

| | |
| --- | --- |
| دامنه | `HLP_DOMAIN` در `.env`؛ زیردامنه‌های `api.` `admin.` `files.` `www.` خودکار |
| API | `/api/v1/...` — مسیرِ قدیمیِ `/api/...` هنوز کار می‌کند ولی منسوخ است |
| سلامت | `/health` (پروسه زنده است؟) و `/ready` (می‌تواند کار کند؟) |
| نقش‌ها | `viewer` / `operator` / `admin` |
| دیتابیس | SQLite با مهاجرتِ شماره‌دار و بکاپِ خودکار |
| استقرار | تونل (پیش‌فرض) یا Docker + Caddy در پوشهٔ `deploy/` |

بدونِ `HLP_DOMAIN` هم همه‌چیز مثل قبل در شبکهٔ خانگی کار می‌کند؛ دامنه
اختیاری است.
