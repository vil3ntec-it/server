# بخشِ پمپ‌بنزین‌ها

این بخش خانهٔ **برنامهٔ نیتیوِ کامپیوتر**ِ هر پمپ بنزین است. هر پمپ پوشه و
رمزِ کاملاً جدا دارد، پس هرچند پمپ که اضافه شود، هیچ عددی از پمپی به پمپِ
دیگر نمی‌رسد.

روشن/خاموش: `HLP_STATIONS` (پیش‌فرض روشن) — پوشه: `HLP_STATIONS_DATA_DIR`
(پیش‌فرض `data/stations`).

## پوشهٔ هر پمپ

```
data/stations/
  <کد پمپ>/
    token.txt      رمزِ برنامهٔ کامپیوتر — می‌نویسد
    readkey.txt    رمزِ کارمند/گوشی — فقط می‌خواند
    station.json   نام و کدِ پمپ            (شاخهٔ station)
    live.json      عکسِ زندهٔ برنامه          (شاخهٔ live)
    inbox.json     پیام‌های رسیده از گوشی‌ها (شاخهٔ inbox)
```

هر سهٔ این فایل‌ها در پشتیبان‌گیریِ خودکارِ پنل هم می‌آیند.

## دو رمز، نه یکی

| رمز | کجا می‌نشیند | اجازه |
| --- | --- | --- |
| `token.txt` | فقط در برنامهٔ نیتیوِ همان پمپ | خواندن و نوشتن |
| `readkey.txt` | در کیو‌آرِ کارمند، اپِ اندروید، شورت‌کاتِ آیفون | فقط خواندن (به‌جز `inbox`) |

کیو‌آرِ کارمند روی کاغذ چاپ می‌شود و دستِ چند نفر می‌گردد. با یک رمزِ
مشترک، همان کاغذ اجازهٔ پاک کردنِ دفترِ پمپ را هم می‌داد — حالا نه: رمزِ
خواندن نه با وب‌سوکت می‌نویسد و نه با HTTP، و سرور خودش جلویش را می‌گیرد.

## راهِ داده

```
برنامهٔ نیتیو ──set live──▶ پوشهٔ همان پمپ ──sub live──▶ اپِ کارمندان (kar/)
              ◀─sub inbox──               ◀─post inbox─ اندروید · آیفون
```

«اصلِ اطلاعات» همان برنامهٔ نیتیو است: تنها اوست که `live` را می‌نویسد.
راهِ برگشت `inbox` است — گوشی‌ها درخواست/یادداشت می‌گذارند و برنامه همان
لحظه می‌بیندشان. پس داده هم می‌رود و هم می‌آید، بی این‌که دو نفر هم‌زمان یک
دفتر را بنویسند و حسابِ کسی خراب شود.

## وب‌سوکت

```
wss://<میزبان>/station?station=<کد>&token=<رمز>
```

از آن به بعد دقیقاً همان پروتکلِ دفترهای `site-sync`:

```
{op:"get",    id, path}            ⇒ {op:"result", id, value}
{op:"set",    id, path, value}     ⇒ {op:"ack", id, ok}
{op:"update", id, path, value}
{op:"sub",    subId, path, event}  ⇒ {op:"event", subId, type, key, value}
{op:"unsub",  subId}
```

مسیرها داخلِ پوشهٔ همان پمپ‌اند: `live`، `inbox`، `station`. پیامِ `connected`
برای رمزِ خواندن `readOnly:true` هم دارد، و هر `op`ی که بنویسد
`{op:"ack", ok:false, error:"read_only"}` می‌گیرد.

## HTTP — برای گوشی و شورت‌کاتِ آیفون

رمز را در `?token=` یا سربرگِ `X-Station-Token` بگذارید. همه‌شان از راهِ
تونل (پورتِ عمومی) هم در دسترس‌اند، هم روی `/api/stations/…` و هم
`/api/v1/stations/…`.

| مسیر | کارش |
| --- | --- |
| `POST /api/stations/enroll` | ثبتِ برنامهٔ نیتیو — پوشه و دو رمز را می‌سازد و برمی‌گرداند |
| `GET /api/stations/:code` | نام، کد، و آخرین بار که برنامه چیزی فرستاد |
| `GET /api/stations/:code/live` | عکسِ زندهٔ کاملِ همان پمپ |
| `GET /api/stations/:code/data/<مسیر>` | هر شاخه‌ای از دفترِ همان پمپ |
| `PUT /api/stations/:code/data/<مسیر>` | نوشتن — فقط رمزِ برنامه |
| `POST /api/stations/:code/inbox` | راهِ برگشت: `{text, kind?, from?}` |
| `GET /api/stations/:code/inbox` | خواندنِ صندوقِ ورودی |
| `DELETE /api/stations/:code/inbox/:id` | پاک کردنِ پیامِ خوانده‌شده — فقط رمزِ برنامه |

⚠️ «پمپ نیست» و «رمز غلط» هر دو `404` می‌گیرند؛ عمداً یکی‌اند تا کسی با
آزمون‌وخطا نفهمد چند پمپ هست و کدشان چیست.

## ثبتِ خودکار — «اگر آدرس نداشت، برایش بساز»

برنامهٔ نیتیو معمولاً هیچ آدرسی از کاربر نمی‌پرسد:

1. سرور را با یک بستهٔ UDP در شبکهٔ خانگی پیدا می‌کند (پورت `4702`).
2. `POST /api/stations/enroll` می‌زند با کد و نامِ پمپِ خودش.
3. پوشه و دو رمز ساخته می‌شود و همان‌جا برمی‌گردد.

چه کسی می‌تواند پمپِ تازه ثبت کند با `HLP_STATIONS_ENROLL` تعیین می‌شود:

- `lan` (پیش‌فرض) — فقط از شبکهٔ خانگی. **از اینترنت هرگز.**
- `off` — هیچ‌کس؛ فقط خودِ پنل پمپ می‌سازد.
- `open` — هر کسی. فقط برای آزمون.

اگر برنامه در شبکهٔ خانگی نیست، پنل یک **کدِ شش‌رقمیِ ده‌دقیقه‌ای** می‌سازد
(`POST /api/stations-admin/pair`) و برنامه همان را در `pin` می‌فرستد. کد
یک‌بارمصرف است، و کدِ غلط هرگز بی‌صدا پمپِ تازه نمی‌سازد.

نصبِ دوبارهٔ همان برنامه: با رمزِ درستِ خودش `enroll` می‌زند و **همان** رمز
و همان پوشه را پس می‌گیرد. با رمزِ غلط `409` می‌گیرد — پمپِ گرفته‌شده به
هیچ‌کس پس داده نمی‌شود.

## پنل

صفحهٔ «پمپ‌بنزین‌ها» (`/stations`). APIاش `/api/stations-admin/…` است و
**هرگز** روی پورتِ عمومی نمی‌آید:

| مسیر | نقشِ لازم |
| --- | --- |
| `GET /` فهرست، با پیش‌نمایشِ رمزها | viewer |
| `GET /:code/keys` رمزهای کامل (در لاگ ثبت می‌شود) | viewer |
| `POST /` ساختِ پمپ · `PUT /:code` نام · `POST /pair` | operator |
| `POST /:code/rotate-read-key` | operator |
| `POST /:code/rotate-token` | admin |
| `DELETE /:code?confirm=<کد>` | admin |

حذف، کلِ پوشه را پاک می‌کند و برگشت ندارد — پس کدِ پمپ را برای تایید
می‌خواهد.
