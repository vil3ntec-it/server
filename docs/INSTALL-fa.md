# نصب از صفر — `install.sh` و دستورِ `vill3n`

بندِ ۱۰.۳ی پرامپت: «من نباید هیچ برنامه‌ای را دستی نصب کنم.» این سند می‌گوید
یک سرورِ **خالیِ** دبیان/اوبونتو با یک دستور چطور کاملاً آماده می‌شود، هر
مرحله چه می‌کند، چه متغیری هست، و بعدش چطور مطمئن شویم کار کرده.

---

## ۱) یک دستور

```bash
curl -fsSL https://api.<دامنه>/install.sh | sudo bash
```

همان فایلِ `install.sh`ِ ریشهٔ همین مخزن است؛ پورتِ عمومیِ پنل (۴۷۰۱) خودش
سروش می‌کند، پس روی سرورِ دومی که می‌سازید نشانی همان سرورِ اول است. اگر
هنوز هیچ سروری ندارید:

```bash
curl -fsSL https://raw.githubusercontent.com/vil3ntec-it/server/main/install.sh | sudo bash
```

**فقط دو چیز پرسیده می‌شود** و بقیه پیش‌فرضِ هوشمند دارد (همه بعداً از پنل
عوض می‌شوند):

| پرسش | اگر خالی بگذارید |
|---|---|
| ✉️ ایمیلِ مدیر | `admin@<دامنه>` |
| 🌐 دامنه (و اگر دامنه دادید، توکنِ تونلِ Cloudflare) | بی دامنه: فقط شبکهٔ خانگی روی HTTP |

⚠️ پرسش‌ها از `/dev/tty` خوانده می‌شوند، نه از ورودیِ استاندارد — چون در
`curl … | bash` ورودیِ استاندارد خودِ اسکریپت است. روی ترمینالی که tty ندارد
(مثلاً یک job)، اسکریپت نمی‌پرسد و از پیش‌فرض‌ها می‌رود.

---

## ۲) نصبِ بی‌پرسش (اسکریپت، CI، آزمون)

```bash
sudo VILL3N_ADMIN_EMAIL=owner@example.com \
     VILL3N_DOMAIN=example.com \
     VILL3N_CF_TOKEN=eyJhIjoi… \
     bash install.sh --non-interactive
```

### گزینه‌های خطِ فرمان

| گزینه | کار |
|---|---|
| `--non-interactive` | هیچ پرسشی؛ همه‌چیز از `VILL3N_*` یا پیش‌فرض |
| `--repair` | همهٔ مرحله‌ها دوباره گذرانده می‌شوند (هر کدام اگر سالم باشد خودش رد می‌شود) |
| `--list-steps` | فقط نامِ مرحله‌ها را چاپ می‌کند و بیرون می‌آید |
| `--root=<مسیر>` | همان `VILL3N_ROOT` |
| `-h` / `--help` | راهنما |

### متغیرهای محیطی — دقیقاً همان‌هایی که پیاده شده‌اند

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `VILL3N_ROOT` | `/srv/vill3n` | ریشهٔ همه‌چیز: کد، داده، پشتیبان، لاگ، رازها |
| `VILL3N_ADMIN_EMAIL` | `admin@<دامنه>` | جوابِ پرسشِ اول |
| `VILL3N_DOMAIN` | خالی | جوابِ پرسشِ دوم (کوچک می‌شود، `https://` و `www.` از آن کنده می‌شود) |
| `VILL3N_CF_TOKEN` | خالی | توکنِ تونلِ Cloudflare؛ در `secrets/cloudflared.token` با ۶۰۰ |
| `VILL3N_NON_INTERACTIVE` | `0` | همان `--non-interactive` |
| `VILL3N_SKIP_SYSTEM` | `0` | `1` ⇒ همهٔ مرحله‌های apt/systemd/ufw/caddy/docker/ollama **رد** می‌شوند و در گزارش «⏭ رد شد» می‌آیند. بی root هم می‌دود. برای آزمون و برای ماشینی که پیش‌نیازها را خودتان نصب کرده‌اید |
| `VILL3N_PANEL_SRC` | — | به‌جای کلون، همین پوشهٔ مخزن کپی می‌شود (آزمون و نصبِ آفلاین) |
| `VILL3N_ACCOUNT_SRC` | — | همان، برای سرورِ حساب (`shop/server`) |
| `VILL3N_PANEL_REPO` / `VILL3N_PANEL_BRANCH` | `…/vil3ntec-it/server` · `main` | از کجا کلون شود |
| `VILL3N_ACCOUNT_REPO` / `VILL3N_ACCOUNT_BRANCH` | `…/vil3ntec-it/shop` · `main` | همان، برای سرورِ حساب |
| `VILL3N_PANEL_PORT` | `4700` | پورتِ پنل (فقط شبکهٔ خانگی و Tailscale) |
| `VILL3N_PUBLIC_PORT` | `4701` | پورتِ عمومی — تونل و برنامه‌ها به این می‌رسند |
| `VILL3N_BIN_DIR` | `/usr/local/bin` (یا `<ریشه>/bin` بی root) | کجا دستورِ `vill3n` نصب شود |
| `VILL3N_RETRY_BASE` | `5` | ثانیهٔ پایهٔ فاصلهٔ تلاش‌ها (۵، ۱۰، ۱۵، ۲۰، ۲۵) |
| `VILL3N_STOP_AFTER` | — | بعد از آن مرحله با کدِ **۷۵** بیرون می‌آید — برای سنجیدنِ «ادامه از نقطهٔ قطع» |

## ۳) بیست‌وسه مرحله — هر کدام چه می‌کند

ترتیب همان است که `bash install.sh --list-steps` می‌دهد. هر مرحله‌ای که تمام
شود یک سطر در `<ریشه>/.install-state` می‌نویسد؛ پس **اجرای دوباره از همان‌جا
ادامه می‌دهد** و کارِ انجام‌شده را تکرار نمی‌کند.

| # | مرحله | چه می‌کند |
|---|---|---|
| ۱ | `detect_system` | توزیع و نسخه، معماری (x86/ARM)، رَم، دیسکِ آزاد، GPU و VRAM، پورتِ SSH. از روی همین‌ها **مدلِ هوش مصنوعی** و **سقفِ حافظهٔ Node** را برمی‌گزیند و در `.install-facts` می‌نویسد. توزیعِ غیرِ apt همین‌جا با پیامِ روشن رد می‌شود |
| ۲ | `ask_questions` | دو پرسش؛ جواب‌ها همان لحظه در `secrets/answers.env` (۶۰۰) می‌نشینند تا قطعِ برقِ وسطِ کار دوباره نپرسد |
| ۳ | `install_base` | `apt-get update` + ca-certificates · curl · git · gnupg · ufw · fail2ban · lm-sensors · smartmontools · unattended-upgrades · openssl |
| ۴ | `install_node` | Node 22: اول NodeSource، نشد تاربالِ رسمیِ nodejs.org (با سنجشِ SHA256)، نشد بستهٔ خودِ توزیع. هیچ‌کدام نشد ⇒ نصب متوقف می‌شود (بی Node پنلی نیست) |
| ۵ | `install_docker` | `get.docker.com`، نشد `docker.io`. نشد ⇒ فقط در گزارش «نشد»؛ پنل بی داکر هم کار می‌کند |
| ۶ | `install_caddy` | بستهٔ توزیع، نشد مخزنِ رسمیِ Caddy، نشد باینریِ `caddyserver.com` + سرویسِ خودمان |
| ۷ | `install_cloudflared` | مخزنِ Cloudflare، نشد بستهٔ `.deb`ِ GitHub |
| ۸ | `install_tailscale` | اسکریپتِ رسمی، نشد بستهٔ توزیع |
| ۹ | `install_ollama` | اسکریپتِ رسمی، نشد باینریِ GitHub. بعدش سقفِ منابع: یک مدل در رَم، یک درخواست هم‌زمان، فقط روی `127.0.0.1` |
| ۱۰ | `create_layout` | درختِ بندِ ۳: `core · sites/clients · apps · desktop-apps · shared · data/core · backups/{daily,weekly,monthly,offsite-queue} · logs/core/install · secrets · docs` — و `secrets/` با ۷۰۰ |
| ۱۱ | `gen_secrets` | `secrets/core.env` با ۶۰۰: کلیدِ تصادفیِ پنل، **رمزِ مدیرِ اولیه**، مسیرها، پورت‌ها، دامنه، مدلِ دستیار، سقفِ حافظه. ⛔ اگر فایل باشد **دست نمی‌خورد** |
| ۱۲ | `fetch_panel` | کدِ پنل در `core/panel` (کلونِ عمق‌۱، نشد تاربالِ GitHub، یا کپی از `VILL3N_PANEL_SRC`) |
| ۱۳ | `fetch_account_server` | سرورِ حساب در `core/account-server/server` (کلونِ sparse فقط زیرپوشهٔ `server`). نشد ⇒ «نشد» در گزارش؛ تا آن وقت ورودِ برنامه‌ها کار نمی‌کند |
| ۱۴ | `install_deps` | `npm ci --omit=dev` برای هر دو، اگر `node_modules` از قبل نباشد |
| ۱۵ | `install_cli` | دستورِ `vill3n` در `/usr/local/bin` (پوسته‌ای روی `homelab-panel/server/bin/vill3n.mjs` که `VILL3N_ROOT` را هم می‌برد) |
| ۱۶ | `setup_systemd` | سرویسِ `vill3n-panel` با `EnvironmentFile=secrets/core.env`، `Restart=always` — یعنی **بعد از هر ری‌استارت و هر قطعِ برق خودش بالا می‌آید** |
| ۱۷ | `setup_caddy` | با دامنه: `<دامنه>`، `api.`، `admin.` ⇒ پورتِ عمومی، و `www.` تغییرِ مسیر. بی دامنه: `http://:80` ⇒ پورتِ عمومی. پیش از نوشتن `caddy validate` می‌شود |
| ۱۸ | `setup_firewall` | `deny incoming`، باز: SSH (پورتِ واقعی از `sshd_config`)، ۸۰، ۴۴۳. **پورتِ پنل فقط از ۱۰/۸، ۱۷۲.۱۶/۱۲، ۱۹۲.۱۶۸/۱۶ و `tailscale0`** — هرگز از اینترنت |
| ۱۹ | `setup_fail2ban` | jailِ `sshd`: ۵ تلاش، ۱۰ دقیقه، بانِ یک‌ساعته |
| ۲۰ | `setup_unattended` | به‌روزرسانیِ امنیتیِ خودکارِ apt |
| ۲۱ | `setup_cloudflared` | اگر توکن داده شده: `cloudflared service install` و سرویسِ دائمی |
| ۲۲ | `pull_model` | مدلِ بندِ ۱ را **در پس‌زمینه** می‌گیرد (چند گیگ است؛ نصب منتظرش نمی‌ماند). پیشرفت در `logs/core/install/ollama-pull-<مدل>.log` |
| ۲۳ | `start_panel` | سرویس را بالا می‌آورد و تا ۶۰ ثانیه `‎/health‎` را می‌پاید |

### انتخابِ مدل از روی سخت‌افزار (مرحلهٔ ۱)

| سخت‌افزار | مدل |
|---|---|
| GPU با ۱۲ گیگ VRAM یا بیشتر | `qwen2.5:14b` |
| GPU (کمتر) | `qwen2.5:7b` |
| بی GPU، رَم ۱۶ گیگ به بالا | `qwen2.5:7b` |
| رَم ۸ تا ۱۶ | `qwen2.5:3b` |
| کمتر از ۸ | `qwen2.5:1.5b` |

سقفِ حافظهٔ خودِ پنل هم یک‌چهارمِ رَم است (کفِ ۵۱۲ مگ، سقفِ ۴ گیگ) و در
`NODE_OPTIONS` می‌نشیند.

## ۴) قاعده‌هایی که نصب‌کننده تضمین می‌کند

- **Idempotent** — اجرای دوباره هیچ‌چیزی را خراب نمی‌کند. آزمون دو اجرای پیاپی
  را بایت‌به‌بایت (با mtime) مقایسه می‌کند و هیچ فایلی نباید عوض شود.
- **ادامه از نقطهٔ قطع** — برق یا اینترنت که وسطِ کار برود، اجرای بعدی از همان
  مرحله می‌رود جلو؛ مرحله‌های قبلی «✔ از قبل انجام شده» می‌شوند.
- **رازها هیچ‌وقت بازنویسی نمی‌شوند** — نه با اجرای دوباره، نه با `--repair`.
  رمزِ عوض‌شده در پنل با نصبِ دوباره برنمی‌گردد.
- **هر دانلود ۵ بار، و برای هر ابزار دستِ‌کم دو منبع** — یک آینه که نبود، بعدی.
- **چیزی که واقعاً لازم نیست، نصب را نمی‌خواباند** — داکر، تونل، Tailscale و
  Ollama اگر نشدند فقط در گزارش «❌ نشد» می‌آیند. فقط Node و کدِ پنل حیاتی‌اند.
- **لاگِ کامل** در `<ریشه>/logs/core/install/install-<تاریخ>-<ساعت>.log`.

## ۵) گزارشِ پایانی

آخرِ کار یک جدول چاپ می‌شود: نشانیِ پنل، نامِ کاربری، **محلِ رمزِ اولیه**،
نشانیِ APIِ عمومی، دستورِ `vill3n`، مسیرِ لاگ، و بعد یک سطر برای هر قلم با
یکی از پنج حال:

```
🆕 نصب شد   ·  ✔ هست   ·  ✔ قبلاً   ·  ⏭ رد شد   ·  ❌ نشد
```

همین جدول در `<ریشه>/.install-report` هم می‌ماند.

رمزِ مدیرِ اولیه در `secrets/core.env` است و فقط root می‌خواندش:

```bash
sudo grep HLP_ADMIN_PASSWORD /srv/vill3n/secrets/core.env
```

پنل همان رمز را سرِ **اولین** بالا آمدن به حسابِ `admin` تبدیل می‌کند و بعد از
آن دیگر دست نمی‌زند — رمزی که خودتان در پنل عوض کنید سرِ جایش می‌ماند.

## ۶) بعدش: دستورِ `vill3n`

```
vill3n status            سرویس، پنل، پورتِ عمومی، سرورِ حساب، تونل، دستیار، پشتیبان‌ها، وابستگی‌ها
vill3n update            پشتیبان ← دریافتِ کدِ تازه ← npm ci ← ری‌استارت
vill3n backup            پشتیبانِ همین حالا (کتابخانه + دیتابیس، رمزشده در صفِ offsite)
vill3n agent on|off      دستیارِ هوشمند
vill3n repair            بررسی و تعمیرِ پوشه‌ها، دسترسی‌ها، ابزارها و سرویس‌ها
vill3n logs [n]          آخرین n سطرِ لاگِ پنل
```

گزینه‌ها: `--root <مسیر>` و `--json` (خروجیِ ماشینی برای `status`).

⚠️ `vill3n` با **کلیدِ محلی** با پنل حرف می‌زند (`data/core/local-admin.key`) —
فایلی که فقط از خودِ همین کامپیوتر خواندنی است. پس نه رمز می‌خواهد نه ورود.
برای تعمیرِ ابزارها و سرویس‌ها `sudo vill3n repair` لازم است؛ بی root فقط
پوشه‌ها و دسترسی‌ها درست می‌شوند و همان را هم می‌گوید.

## ۷) چطور مطمئن شویم نصب درست بوده

```bash
# ۱) سرویس و پنل
sudo systemctl is-active vill3n-panel        # باید active باشد
curl -fsS http://127.0.0.1:4700/health       # JSONِ سلامتِ پنل
curl -fsS http://127.0.0.1:4701/health       # پورتِ عمومی (تونل به این می‌رسد)

# ۲) یک نگاهِ کامل
sudo vill3n status

# ۳) نصب‌کننده از بیرون هم می‌آید (همان فایل)
curl -fsS https://api.<دامنه>/install.sh | head -3

# ۴) از راهِ دامنه و تونل
curl -fsS https://api.<دامنه>/api/health

# ۵) پشتیبان واقعاً گرفته و رمز می‌شود
sudo vill3n backup
ls /srv/vill3n/backups/manual /srv/vill3n/backups/offsite-queue

# ۶) فایروال
sudo ufw status verbose                      # ۴۷۰۰ فقط از شبکهٔ خانگی

# ۷) چه چیزی نصب شد و چه چیزی نه
cat /srv/vill3n/.install-report
```

`vill3n status` سبز یعنی: سرویس روشن، پنل و پورتِ عمومی جواب می‌دهند، سرورِ
حساب بالاست، رمزنگاریِ پشتیبان آماده است و هیچ وابستگیِ اجباری‌ای کم نیست.

## ۸) چیزی خراب شد

| نشانه | کار |
|---|---|
| نصب وسطِ کار افتاد | همان دستور را دوباره بزنید؛ از همان مرحله ادامه می‌دهد. `cat <ریشه>/.install-state` می‌گوید تا کجا رفته |
| چیزی پاک یا خراب شده | `sudo vill3n repair` |
| پنل بالا نمی‌آید | `sudo vill3n logs 200` یا `journalctl -u vill3n-panel -n 200` |
| دامنه جواب نمی‌دهد ولی پنل بالاست | Caddy و تونل: `systemctl status caddy cloudflared` و `/etc/caddy/Caddyfile` |
| توزیعِ غیرِ apt | پیش‌نیازها را دستی نصب کنید و `VILL3N_SKIP_SYSTEM=1` بزنید — بقیهٔ کار همان است |

راهنمای کاملِ خرابی‌ها (قطعِ برق، پر شدنِ دیسک، خرابیِ دیتابیس، بازیابیِ
پشتیبان، سرویسِ افتاده، دمای بالا): `docs/RUNBOOK-fa.md`.

## ۹) آزمون

```bash
cd homelab-panel/server
npm run test:install            # نصب‌کننده و دستورِ vill3n
npm run test:backup-rotation    # رمزنگاری، چرخش، تستِ بازیابی، صفِ offsite
npm run test:selfheal           # خودترمیمی و مرزِ دسترسیِ تعمیر
```

⚠️ **مسیرِ واقعیِ apt/systemd/ufw/caddy/ollama در آزمون نمی‌دود** — نه root
هست نه اینترنتِ آزاد. آن مسیر فقط `bash -n` و بازبینیِ چشمی دارد. آن‌چه
کامل سنجیده می‌شود مسیرِ `VILL3N_SKIP_SYSTEM=1` است: ماشینِ حالت، ادامه از
نقطهٔ قطع، ساختارِ پوشه‌ها، رازها و دسترسی‌هایشان، کد، CLI، گزارش، و بعد
خودِ پنل که با همان `core.env` بالا می‌آید و `vill3n` رویش می‌دود.
