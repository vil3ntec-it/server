# استقرار

دو راه برای رساندنِ سرورِ خانگی به اینترنت هست. هر دو کار می‌کنند و هر دو
همان قاعده را نگه می‌دارند: **کلاینت فقط `api.YOURDOMAIN.com` را می‌شناسد.**

| | Cloudflare Tunnel | Caddy (این پوشه) |
| --- | --- | --- |
| IP عمومی لازم است؟ | نه | بله |
| پورت روی مودم باز شود؟ | نه | بله (۸۰ و ۴۴۳) |
| گواهیِ TLS | با Cloudflare | خودکار از Let's Encrypt |
| مناسبِ | سرورِ خانگی پشتِ مودم | VPS یا خانه با IP ثابت |

پنل از قبل تونل را دارد (`src/tunnel.js`) و به‌صورت پیش‌فرض روشن است. اگر
خانه‌اید و مودم اجازهٔ باز کردنِ پورت نمی‌دهد، **همان را نگه دارید** و به این
پوشه کاری نداشته باشید.

این پوشه برای وقتی است که سرور IP عمومی دارد یا به VPS رفته است.

## راه‌اندازی

```bash
cd deploy
./setup.sh
```

هر چه ماشین می‌تواند خودش انجام دهد، می‌دهد: `.env` را می‌سازد، `SECRET_KEY` را
تولید و در همان فایل می‌نویسد، و دسترسیِ فایل را به ۶۰۰ می‌بندد. بعد بقیه را
اسم‌به‌اسم می‌گوید — دامنه، رکوردهای DNS، پورت‌های باز، کلیدِ پیامک — و اگر چیزی
بدونِ شما حل نمی‌شود با کدِ ۱ بیرون می‌آید.

مهم‌ترین کارش این است که **پیش از** بالا آمدن می‌گوید کدام رکوردِ DNS جا افتاده.
بدونِ این، همان را از روی خطای گنگِ Let's Encrypt می‌فهمید — بعد از اینکه چند
بار به سقفِ نرخِ صدور خوردید.

وقتی همه‌چیز سبز شد:

```bash
./setup.sh --up               # یا: docker compose up -d --build
```

دستی هم می‌شود، ولی چیزی به شما یادآوری نمی‌کند:

```bash
cp .env.example .env
openssl rand -hex 32          # مقدارش را در SECRET_KEY بگذارید
docker compose up -d
```

اگر `SECRET_KEY` یا `DOMAIN` خالی باشد، compose عمداً بالا نمی‌آید. راز نباید
«یک روز بعد» گذاشته شود.

## ورودِ کاربرانِ اپ (کدِ شش‌رقمی)

کلِ `.env` از راهِ `env_file` به کانتینرِ پنل می‌رسد، پس تنظیماتِ `OTP_*` را
همان‌جا بگذارید:

```
OTP_SMS_PROVIDER=kavenegar
OTP_SMS_KEY=...
OTP_SMS_SENDER=...
```

یا ایمیل (`OTP_EMAIL_HOST` و بقیه). تا وقتی هیچ‌کدام نباشد، ورود کار می‌کند ولی
کد به‌جای پیامک در «پنل ← لاگ‌ها» نوشته می‌شود — برای آزمایش خوب است، برای
کاربرِ واقعیِ اپِ اندروید نه.

نمونه‌های کامل در `.env.example` هست.

## DNS

پنج رکورد، همه به IP همین سرور. `setup.sh` خودش می‌سنجدشان:

```
A   YOURDOMAIN.com        <IP>
A   api.YOURDOMAIN.com    <IP>
A   admin.YOURDOMAIN.com  <IP>
A   files.YOURDOMAIN.com  <IP>
A   www.YOURDOMAIN.com    <IP>
```

## سخت‌تر کردنِ پنل

`admin.` جایی است که فایل‌منیجر و کنترلِ پروسه‌ها هست. در `Caddyfile` دو خطِ
کامنت‌شده هست که آن را فقط از داخلِ شبکهٔ خانگی باز می‌کند؛ اگر از بیرون به
پنل نیاز ندارید، از کامنت درشان بیاورید.

## مهاجرت به سرورِ دیگر

۱. `docker compose down` روی سرورِ قدیم
۲. کپیِ حجمِ `panel-data` و پوشهٔ `sites`
۳. `docker compose up -d` روی سرورِ تازه
۴. رکوردهای DNS به IP تازه

هیچ کلاینتی به‌روزرسانی نمی‌خواهد. همین دلیلِ وجودِ کلِ این ساختار است.
