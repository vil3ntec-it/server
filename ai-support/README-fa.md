# دستیارِ پشتیبانیِ هوشمند — راهنمای کامل

یک هوشِ مصنوعیِ واقعی که **برنامه را خوب می‌شناسد ولی هیچ قدرتی روی آن ندارد**.

```
KNOW EVERYTHING IT IS ALLOWED TO KNOW  —  CHANGE NOTHING
```

- **معماری و مرزِ امنیتی:** [ARCHITECTURE-fa.md](ARCHITECTURE-fa.md)
- **وابستگیِ npm:** هیچ. فقط Node.js 20 به بالا.
- **پورت:** ۸۷۸۸ (سرورِ اصلیِ برنامه روی ۸۷۸۷ است و این دو هیچ ارتباطی ندارند)

---

## ۱. شروعِ سریع (سه دقیقه)

```bash
cd ai-support
node bin/detect-hardware.mjs      # ببین کامپیوترت چه مدلی را می‌کِشد
node src/index.js                 # همین حالا کار می‌کند
```

سرویس **بدونِ هیچ مدلی هم بالا می‌آید** و جواب می‌دهد — جواب‌ها مستقیم از
مستندات در می‌آیند. برای اینکه واقعاً «فکر کند»، مرحلهٔ بعد را انجام بده.

### آزمایش

```bash
curl http://127.0.0.1:8788/ai/support/health
curl "http://127.0.0.1:8788/ai/support/search?q=میانبر"
```

## ۲. روشن کردنِ مغز (مدلِ زبانی)

### گامِ ۱ — Ollama را نصب کن

- **ویندوز / مک:** از <https://ollama.com/download>
- **لینوکس:** `curl -fsSL https://ollama.com/install.sh | sh`

### گامِ ۲ — مدلی که سخت‌افزارت گفته را بگیر

```bash
node bin/detect-hardware.mjs      # اسمِ مدل را می‌گوید
ollama pull qwen2.5:3b-instruct-q4_K_M   # ← همانی که پیشنهاد داد
ollama pull nomic-embed-text             # برای جست‌وجوی معنایی
```

### گامِ ۳ — تنظیمات را بنویس و ایندکس را بساز

```bash
node bin/detect-hardware.mjs --apply     # config.local.json را می‌سازد
node bin/build-index.mjs                 # ایندکس + بردارها
node src/index.js
```

### جدولِ انتخابِ مدل

| سخت‌افزار | مدل | حال‌وروزش |
|---|---|---|
| کارت گرافیک ۱۶ گیگ به بالا | `qwen2.5:14b-instruct-q4_K_M` | خیلی خوب، سریع |
| کارت گرافیک ۱۰–۱۶ گیگ | `qwen2.5:7b-instruct-q4_K_M` | خوب و سریع |
| کارت گرافیک ۴–۱۰ گیگ | `qwen2.5:3b` یا `7b` | خوب |
| بدونِ کارت، رَم ۱۶+ | `qwen2.5:3b-instruct-q4_K_M` | کند ولی قابلِ استفاده |
| بدونِ کارت، رَم ۸–۱۶ | `qwen2.5:1.5b-instruct-q4_K_M` | ساده ولی سبک |
| رَمِ کمتر از ۸ | — | حالتِ «فقط بازیابی» |

عوض کردنِ مدل یک خط است: `AI_LLM_MODEL` در فایلِ `.env`.

## ۳. وصل کردن به برنامه

ویجت از قبل داخلِ `index.html` هست: **رباتِ دستیار ← تبِ «پشتیبانی هوشمند»**.

### اگر پنلِ سرورِ خانگی را داری (حالتِ عادی) — هیچ کاری لازم نیست

`homelab-panel` خودش این سرویس را با بالا آمدنش روشن می‌کند و مسیرِ
`/ai/support` را روی همان پورتِ عمومیِ سرور پراکسی می‌کند.

یعنی سایت با **همان آدرسی که برای همگام‌سازی استفاده می‌کند** به دستیار هم
می‌رسد. نه پورتِ تازه‌ای لازم است، نه تونلِ دوم، نه تنظیمی در مرورگر.

> این تنها راهی است که از اینترنت کار می‌کند: سرویس روی `127.0.0.1` گوش می‌دهد
> و تونلِ خانه فقط یک پورت را بیرون می‌دهد. پورتِ ۸۷۸۸ از بیرون در دسترس نیست
> و **نباید هم باشد**.

### اگر سرویس را دستی و جدا اجرا می‌کنی

آن‌وقت باید خودت آدرس بدهی — در کنسولِ مرورگر:

```js
localStorage.setItem('pumpAiUrl', 'http://192.168.1.50:8788');
location.reload();
```

و روی سرویس، دامنهٔ سایت را اجازه بده:

```
AI_ALLOWED_ORIGINS=https://yaqobipump.top
AI_HOST=0.0.0.0
```

> ⚠️ با `AI_HOST=0.0.0.0` سرویس روی شبکه باز می‌شود. حتماً `AI_ALLOWED_ORIGINS`
> را پر کن. اگر پنل را داری، این کار لازم نیست — پراکسیِ پنل امن‌تر است.

## ۴. کاری که نمی‌کند — و نمی‌تواند بکند

نه به‌خاطرِ اینکه «اجازه ندارد»، بلکه چون **ابزارش وجود ندارد**:

| ممنوع | چرا ممکن نیست |
|---|---|
| تغییر/حذفِ دادهٔ برنامه | مسیرِ `server/data` در فهرستِ ممنوع؛ سرویس اصلاً بازش نمی‌کند |
| ساخت/حذف/تغییرِ حساب | هیچ ابزارِ نوشتنی در رجیستری نیست |
| دیدنِ رمز و توکن | لایهٔ `redact` روی ورودی و خروجی |
| اجرای دستورِ سیستم | هیچ `child_process` ای در کدِ سرویس نیست — تستِ خودکار می‌گردد |
| تغییرِ فونت/رنگ/ظاهر | سرویس فقط متن و داده برمی‌گرداند؛ ویجت هیچ‌وقت HTMLِ مدل را اجرا نمی‌کند |
| تغییرِ تنظیمات | دروازه فقط `GET` دارد |

اگر مرز شکسته باشد، سرویس **بالا نمی‌آید** و می‌گوید کجا شکسته.

## ۵. مصرفِ منابع — «کامپیوتر نسوزد»

پنج ترمز، همه قابلِ تنظیم در `.env`:

| ترمز | متغیر | پیش‌فرض | کارش |
|---|---|---|---|
| هم‌زمانی | `AI_MAX_CONCURRENT` | ۱ | فقط یک تولید در لحظه |
| صف | `AI_MAX_QUEUE` | ۸ | بیشتر از این → جوابِ ساده به‌جای انتظار |
| پنجرهٔ متن | `AI_NUM_CTX` | ۲۰۴۸ | کوچک = سریع و کم‌مصرف |
| بیکاری | `AI_KEEP_ALIVE` | 5m | مدل از رَم بیرون می‌رود |
| نگهبانِ بار | `AI_LOAD_LIMIT` | ۰٫۸۵ | سیستم شلوغ → حالتِ «فقط بازیابی» |

به‌علاوهٔ **کشِ پاسخ**: سؤالِ تکراری اصلاً به مدل نمی‌رسد.

روی کامپیوترِ ضعیف:

```
AI_MAX_CONCURRENT=1
AI_LOAD_LIMIT=0.6
AI_NUM_CTX=1536
AI_MAX_TOKENS=300
AI_KEEP_ALIVE=2m
```

بدترین حالتِ ممکن «جوابِ ساده‌تر» است، نه «کامپیوترِ قفل‌شده».

## ۶. سطحِ دسترسی

| نقشِ برنامه | سطح | چه می‌بیند |
|---|---|---|
| مشتریِ QR | `PUBLIC` | راهنمای عمومی |
| کارمند / نظاره‌گر | `USER` | کارِ روزمره |
| مدیر | `ADMIN` | همه‌چیز جز `INTERNAL` |

**سطحِ ADMIN فقط با `AI_ADMIN_TOKEN` صادر می‌شود.** بدونِ آن، حتی اگر برنامه
بگوید «من مدیرم»، سطح `USER` می‌ماند. دلیلش در `src/security/auth.js` نوشته شده:
توکنِ داخلیِ برنامه در `index.html`ِ باز روی اینترنت است، پس نمی‌تواند مبنای
اعتماد باشد.

```
AI_ADMIN_TOKEN=یک-رمزِ-طولانیِ-فقط-مالِ-خودت
```

## ۷. افزودن به دانش

فایلِ `.md` تازه در `knowledge/` بساز:

```markdown
---
id: my-feature
title: عنوانِ سند
feature: نامِ قابلیت
version: 2.9.316
access: USER
updated: 2026-08-14
tags: [کلمه, کلمه]
synonyms:
  - جوری که کاربر واقعاً می‌پرسد
  - یک جورِ دیگرش
links:
  - نامِ لینک | https://example.com
shortcuts:
  - Ctrl+K | کاری که می‌کند
---

## سرتیتر
متن…
```

بعد `node bin/build-index.mjs`.

**مهم‌ترین فیلد `synonyms` است.** همان‌جوری بنویس که کاربر می‌پرسد، نه آن‌جوری
که در مستندات نوشته می‌شود. کاربر می‌نویسد «رمزم یادم نیست»، نه «بازیابی اعتبار
حساب» — و همین باعث می‌شود پیدایش کند.

هر سند باید `version` و `updated` داشته باشد تا اگر برنامه عوض شد، دستیار
اطلاعاتِ کهنه را به‌عنوان اطلاعاتِ فعلی ندهد.

⚠️ **هرگز رمز یا توکن داخلِ سند ننویس.** یک تستِ خودکار همهٔ اسناد را می‌گردد و
اگر چیزی شبیهِ راز پیدا کند، شکست می‌خورد.

۱۲۲ تست، بدونِ نیاز به Ollama:

| مجموعه | چه چیزی را ثابت می‌کند |
|---|---|
| امنیت | دادهٔ برنامه خواندنی نیست، اسرار پنهان می‌شوند، نشستِ جعلی رد می‌شود |

| بازیابی و دانش | سؤالِ کاربر سندِ درست را پیدا می‌کند؛ سطحِ دسترسی نشت نمی‌کند |

## ۹. مسیرهای HTTP

| مسیر | متد | کار |
|---|---|---|
| `/ai/support/health` | GET | وضعیتِ سرویس، مدل، بار، ابزارها |
| `/ai/support/session` | POST | گرفتنِ نشست |
| `/ai/support/chat` | POST | پرسیدن |
| `/ai/support/search` | GET | جست‌وجوی معنایی |
| `/ai/support/documentation` | GET | مستندات |
| `/ai/support/faq` | GET | پرسش‌های پرتکرار |
| `/ai/support/info` | GET | اطلاعاتِ یک قابلیت |
| `/ai/support/links` | GET | لینک‌های رسمی |
| `/ai/support/shortcuts` | GET | میانبرها |
| `/ai/support/index` | GET | ایندکسِ سبک برای ویجتِ آفلاین |
| `/ai/support/memory` | GET/POST/DELETE | حافظهٔ خودِ کاربر |

هیچ متدِ نوشتنی‌ای روی دادهٔ برنامه وجود ندارد. `POST /chat` گفت‌وگوست، نه
تغییرِ داده. `/memory` هم ترجیحاتِ خودِ کاربر در پوشهٔ خودِ سرویس است — هیچ
ابزارِ AI به آن دست ندارد.

## ۱۰. Docker

```bash
cd ai-support
docker compose up -d
```

`docker-compose.yml` دو سرویس دارد: خودِ دستیار و Ollama. حجمِ مدل‌ها در یک
volume می‌ماند تا با هر بار بالا آمدن دوباره دانلود نشود.

اولین بار، مدل را داخلِ کانتینر بگیر:

```bash
docker compose exec ollama ollama pull qwen2.5:3b-instruct-q4_K_M
docker compose exec ollama ollama pull nomic-embed-text
```

> روی کارتِ NVIDIA، بخشِ `deploy.resources` در فایل را از حالتِ توضیح در بیاور.

## ۱۱. اجرای دائم

**لینوکس (systemd):**

```bash
sudo cp ai-support.service /etc/systemd/system/
sudo systemctl enable --now ai-support
```

**ویندوز:** فایلِ `start-windows.bat` را در پوشهٔ Startup بگذار.

## ۱۳. وقتی چیزی کار نمی‌کند

| نشانه | علت | کار |
|---|---|---|
| «سرویسِ پشتیبانی در دسترس نیست» | سرویس روشن نیست | `node src/index.js` |

| کامپیوتر کند می‌شود | ترمزها شل‌اند | `AI_LOAD_LIMIT=0.6` و مدلِ کوچک‌تر |
| «کمی آرام‌تر» | محدودیتِ نرخ | `AI_...` در `.env` یا کمی صبر |
| سند تازه دیده نمی‌شود | ایندکس کهنه است | `node bin/build-index.mjs` |
