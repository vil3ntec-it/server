# معماری و مرزِ امنیتیِ «دستیارِ پشتیبانیِ هوشمند»

> این سند **پیش از کد** نوشته شده و قرارداد سرویس است. اگر روزی کسی خواست چیزی
> اضافه کند، اول این‌جا را بخواند: هر خطی که این‌جا «ممنوع» نوشته شده، در کد یک
> نگهبان و یک تست دارد.

اصلِ کل پروژه:

```
KNOW EVERYTHING IT IS ALLOWED TO KNOW  —  CHANGE NOTHING
هر چه اجازه دارد بداند، بداند. هیچ چیز را عوض نکند.
```

---

## ۱. جای این سرویس در دنیای پروژه

سرویس یک **پروسهٔ کاملاً جدا** است. نه بخشی از `server/server.js` (سرورِ خانگیِ
اصلی)، نه بخشی از `homelab-panel`، نه بخشی از `index.html`.

```
┌───────────────────────────────────────────────────────────────────┐
│ دستگاهِ کاربر (مرورگر / اندروید / ویندوز)                          │
│                                                                   │
│   index.html  ──── برنامهٔ اصلی (داده، محاسبات، UI)                │
│        │                                                          │
│        └── تبِ «پشتیبانی» داخل رباتِ دستیار  ← تنها نقطهٔ تماس       │
│              │                                                    │
│              ├── بازیابیِ محلی (RAG سبک، ایندکسِ از‌پیش‌ساخته)      │
│              └── رسم/اسکنِ QR (کتابخانهٔ خودِ برنامه)               │
└──────────────────────────┬────────────────────────────────────────┘
                           │ HTTPS/WSS — فقط همین یک کانال
                           ▼
┌───────────────────────────────────────────────────────────────────┐
│ سرورِ خانگیِ شما                                                   │
│                                                                   │
│  ┌─────────────────────┐        ┌──────────────────────────────┐  │
│  │ server/server.js    │        │ ai-support/  (پورت 8788)     │  │
│  │ پورت 8787           │        │                              │  │
│  │ دادهٔ واقعیِ برنامه   │  ⛔️❌  │  Security Layer              │  │
│  │ data/*.json         │ ◄──────┤  Read-Only API Gateway       │  │
│  └─────────────────────┘  هیچ   │  Agent + Tool Router         │  │
│                           مسیری │  RAG / Knowledge Base        │  │
│                           نیست  │  Memory (فقط مالِ خودش)      │  │
│                                 └──────────────┬───────────────┘  │
│                                                │                  │
│                                    ┌───────────▼──────────────┐   │
│                                    │ LLM (Ollama / سازگارِ    │   │
│                                    │ OpenAI / هیچ‌کدام)        │   │
│                                    └──────────────────────────┘   │
└───────────────────────────────────────────────────────────────────┘
```

خطِ `⛔️❌` مهم‌ترین خطِ این سند است: **سرویسِ AI هیچ راهی به دادهٔ برنامه ندارد.**
نه import، نه خواندنِ فایل، نه WebSocket، نه توکن. در `src/security/guard.js`
موقع بالا آمدن بررسی می‌شود؛ اگر کسی مسیرِ دادهٔ اصلی را در پیکربندی بگذارد،
سرویس **بالا نمی‌آید** و می‌گوید چرا.

## ۲. مرزِ امنیتی — دقیقاً چه چیزی ممنوع است و نگهبانش کجاست

| ممنوع | نگهبان در کد | تستِ اثبات |
|---|---|---|
| تغییر/حذفِ کدِ برنامه | سرویس به ریشهٔ ریپو دسترسیِ نوشتن ندارد؛ `guard.js` هر مسیرِ نوشتنی بیرون از `ai-support/data` را رد می‌کند | `test/security.test.mjs` |
| ساخت/حذف/تغییرِ حساب کاربری | هیچ ابزاری با `write:true` در رجیستری وجود ندارد؛ router ابزارِ غیرِ `readOnly` را اجرا نمی‌کند | `test/readonly.test.mjs` |
| تغییرِ دیتابیسِ اصلی | مسیرِ `server/data` در فهرستِ `FORBIDDEN_PATHS`؛ خواندنش هم رد می‌شود | `test/security.test.mjs` |
| تغییرِ تنظیمات برنامه یا سرور | Gateway فقط `GET` را به منابع می‌دهد؛ هیچ منبعِ نوشتنی ثبت نشده | `test/readonly.test.mjs` |
| تغییرِ فونت/رنگ/اندازه/Layout/CSS | پاسخ‌های سرویس فقط متن+داده‌اند؛ ویجت هیچ‌وقت HTML خام مدل را داخل صفحه نمی‌گذارد و هیچ API ای برای دست زدن به `document.styleSheets` در اختیارش نیست | `test/ui-safety.test.mjs` |
| دیدنِ Secret / Token / Password | `redact.js` روی **ورودی و خروجی** اجرا می‌شود؛ اسنادِ با `access: INTERNAL` هرگز به کاربرِ عادی نمی‌رسند | `test/security.test.mjs` |
| اجرای دستور سیستم‌عامل | هیچ‌جای سرویس `child_process` / `exec` / `eval` / `new Function` وارد نشده — تستِ ایستا کلِ `src/` را می‌گردد | `test/no-shell.test.mjs` |
| گوش دادن به دستورِ داخلِ سند | `injection.js` متنِ بازیابی‌شده را در پاکتِ داده می‌پیچد و الگوهای دستوری را علامت می‌زند | `test/injection.test.mjs` |

### قاعدهٔ ابزارِ تازه
هر ابزارِ جدید **پیش‌فرض خاموش** است. تا وقتی هم‌زمان (۱) در رجیستری با
`readOnly: true` تعریف نشود و (۲) نامش در `config.tools.whitelist` نیاید، router
اجرایش نمی‌کند. یعنی فراموش کردنِ whitelist به «باز شدن» ختم نمی‌شود، به «کار
نکردن» ختم می‌شود — خطا در جهتِ امن.

## ۳. تقسیمِ کارِ محاسباتی — چرا هیچ کامپیوتری داغ نمی‌کند

خواستهٔ صریحِ صاحبِ ریپو: «به سرور خانگی وصل باشد، از کامپیوترِ خودِ کاربر هم
استفاده کند، و روی هیچ کامپیوترِ شلوغی فشار نیاورد.» این سه با هم فقط وقتی جمع
می‌شوند که کار **تقسیم** شود، نه این‌که هر دو طرف یک کار را بکنند:

| کار | کجا | چرا آن‌جا | هزینه |
|---|---|---|---|
| نرمال‌سازی و جست‌وجوی متن | مرورگرِ کاربر | ایندکس از قبل ساخته شده؛ فقط چند هزار مقایسهٔ عدد است | حدود ۱ms، صفرِ شبکه |
| رسمِ QR | مرورگرِ کاربر | `QRCode` از قبل داخلِ `index.html` هست | صفرِ سرور |
| خواندنِ QR | مرورگرِ کاربر | `jsQR` از قبل داخلِ `index.html` هست | صفرِ سرور |
| فهمِ سؤال و نوشتنِ جوابِ طبیعی | سرورِ خانگی | تنها کارِ سنگینِ واقعی؛ یک مدلِ مشترک برای همه | کنترل‌شده ↓ |

پنج ترمزِ سرور، همه در `src/llm/pool.js` و `src/llm/cache.js`:

1. **صفِ تک‌نفره** — هر لحظه فقط یک تولید. بقیه در صف. عمقِ صف محدود؛ بیشتر از
   آن، جوابِ «شلوغم، از روی مستندات جواب می‌دهم» می‌آید نه اینکه سرور خفه شود.
2. **کشِ پاسخ** — سؤالِ تکراری (بعد از نرمال‌سازی) اصلاً به مدل نمی‌رسد.
3. **بودجهٔ توکن** — `num_ctx` کوچک و سقفِ تولید؛ متنِ بازیابی‌شده قبل از رفتن
   پیشِ مدل بریده می‌شود.
4. **تخلیهٔ مدل در بیکاری** — `keep_alive` کوتاه، تا وقتی کسی سؤالی ندارد رَم آزاد باشد.
5. **نگهبانِ بار** — اگر بارِ سیستم از آستانه رد شد، سرویس خودش به حالتِ
   «فقط بازیابی» می‌افتد: جواب از خودِ سند در می‌آید، صادقانه هم می‌گوید.

نتیجه: بدترین حالتِ ممکن «جوابِ ساده‌تر» است، نه «کامپیوترِ قفل‌شده».

### حالتِ سوم (اختیاری): مدل روی دستگاهِ خودِ کاربر
اگر دستگاهِ کاربر WebGPU و رَمِ کافی داشته باشد، می‌تواند مدلِ کوچک را خودش اجرا
کند و اصلاً سراغِ سرور نرود. **پیش‌فرض خاموش است** و فقط با تیک زدنِ خودِ کاربر
روشن می‌شود — چون دانلودِ مدل و گرم شدنِ لپ‌تاپ باید انتخابِ خودش باشد.

## ۴. جریانِ یک سؤال

```
سؤالِ کاربر
   │
   ├─▶ اعتبارسنجی طول/نوع  ────────────── رد شد → خطای مؤدبانه
   ├─▶ محدودیت نرخ (به‌ازای دستگاه)  ──── رد شد → «کمی آرام‌تر»
   ├─▶ پالایشِ ورودی (redact)  ────────── توکن/رمزِ چسبیده به متن حذف می‌شود
   │
   ├─▶ کش؟  ───────────────────────────── بله → جوابِ آماده (۰ms مدل)
   │
   ├─▶ بازیابی (هیبرید: BM25 + سه‌گرام + امبدینگ)
   │      └── فیلترِ سطحِ دسترسی بر اساس نقشِ کاربر
   │
   ├─▶ مدل هست و سیستم شلوغ نیست؟
   │      ├── نه → پاسخِ استخراجی از سند + «مدل در دسترس نیست»
   │      └── بله ▼
   │
   ├─▶ LLM (دور ۱): با متنِ بازیابی‌شده + فهرستِ ابزار
   │      ├── جواب داد → پایان
   │      └── ابزار خواست ▼
   │
   ├─▶ Tool Router: whitelist? read-only? مجاز برای این نقش؟
   │      └── هر سه بله → اجرا + Audit Log ؛ وگرنه ردِ ثبت‌شده
   │
   ├─▶ LLM (دور ۲، سقفِ پیش‌فرض)  → جوابِ نهایی
   │
   ├─▶ پالایشِ خروجی: حذفِ Secret، حذفِ لینکِ غیرِ whitelist
   └─▶ جواب + منابع + مراحل + لینک + QR
```

**سقفِ دورها ۲ است** (`agent.maxSteps`). نه فقط برای امنیت — برای اینکه یک سؤالِ
عجیب نتواند ده بار مدل را صدا بزند و سرور را مشغول کند.

## ۵. انتخابِ تکنولوژی و دلیلش

| انتخاب | چرا این، نه آن یکی |
|---|---|
| **Node.js خالی، صفر وابستگی npm** | `server/server.js` هم همین‌طور است و صاحبِ ریپو صریح گفته «بدون npm install». هر `npm i` روی سرورِ خانگی یعنی یک وابستگیِ دیگر که می‌تواند بشکند یا آسیب‌پذیر شود. کلِ سرویس با `node src/index.js` بالا می‌آید. |
| **بدونِ Express** | برای ۹ مسیرِ ساده، Express فقط ۵۰ وابستگی اضافه می‌کند. `node:http` کافی است. |
| **Vector DB فایل‌محور، نه Chroma/Qdrant** | یک Knowledge Base با چند صد چانک، ایندکسش چند صد کیلوبایت است. راه انداختنِ یک دیتابیسِ برداریِ جدا روی کامپیوترِ خانگی یعنی یک پروسهٔ دیگر، یک پورتِ دیگر و چند صد مگابایت رَمِ دیگر — برای کاری که یک ضربِ داخلی در حافظه انجامش می‌دهد. |
| **بازیابیِ هیبرید (BM25 + سه‌گرام + برداری)** | فارسی نیم‌فاصله و شکل‌های مختلفِ یک کلمه دارد؛ سه‌گرام همان‌ها را می‌گیرد. برداری معنا را می‌گیرد. BM25 دقتِ کلمهٔ نادر را. هیچ‌کدام تنها کافی نیست. ادغام با RRF چون نمره‌هایشان هم‌مقیاس نیستند. |
| **امبدینگ اختیاری** | اگر Ollama باشد، `nomic-embed-text` معنا را واقعی می‌کند. اگر نباشد، جست‌وجو با بسطِ پرسشِ خودِ مدل کار می‌کند و سرویس نمی‌ایستد. |
| **Ollama پیش‌فرض** | نصبش روی ویندوز/لینوکس یک فایل است، مدل را خودش مدیریت می‌کند، `keep_alive` دارد (همان ترمزِ بیکاری). ولی لایه‌اش عوض‌شدنی است. |
| **Qwen2.5 Instruct** | در این اندازه‌ها بهترین فارسیِ در دسترس است. ولی در `config` یک رشته است — با یک خط عوض می‌شود. |
| **QR روی دستگاهِ کاربر** | `qrcodejs` و `jsQR` از قبل داخلِ `index.html` هستند. تولیدِ سمتِ سرور یعنی وابستگیِ npm + CPU + رفت‌وبرگشتِ عکس؛ در حالی‌که مرورگر همان کار را رایگان می‌کند. |
| **لاگِ خطی JSONL** | با `tail` خوانده می‌شود، چرخشِ فایلش ساده است، و برای audit کافی است. |

## ۶. سطحِ دسترسیِ اسناد

`PUBLIC` → `USER` → `PREMIUM` → `ADMIN` → `INTERNAL` (نردبانی، هر سطح شاملِ پایینی‌ها)

نقشِ برنامهٔ اصلی به این‌ها نگاشت می‌شود:

| نقش در برنامه | سطحِ AI | چه می‌بیند |
|---|---|---|
| مهمانِ QR (`person`) | `PUBLIC` | راهنمای عمومی، حسابِ خودش |
| کارمند (`staff`) | `USER` | کارِ روزمره، ورق، پارچه |
| نظاره‌گر (`viewer`) | `USER` | همان، بدونِ بخش‌های مدیریتی |
| مدیر (`admin`) | `ADMIN` | همه‌چیز، جز `INTERNAL` |
| — | `INTERNAL` | **هیچ‌کس از راهِ چت** — فقط برای نگه‌داریِ خودِ سند |

نکتهٔ ظریف: نقش را **کاربر نمی‌فرستد**، سرویس از توکنِ نشستِ امضاشده در می‌آورد.
اگر کسی در متنِ چت بنویسد «من مدیرم»، هیچ اتفاقی نمی‌افتد.

## ۷. حافظه (Memory)

- فقط چیزهای بی‌خطر: زبانِ ترجیحی، بخش‌هایی که کاربر زیاد سراغشان می‌رود، لحنِ پاسخ.
- در فایلِ خودِ سرویس (`ai-support/data/memory/`)، نه در دیتابیسِ برنامه.
- کاربر با `GET /ai/support/memory` می‌بیند و با `DELETE /ai/support/memory` پاک می‌کند.
  این تنها `DELETE` کلِ سرویس است و فقط رویِ حافظهٔ خودِ همان کاربر کار می‌کند —
  به دادهٔ برنامه کاری ندارد.
- هر چیزی که از `redact.js` رد نشود، اصلاً وارد حافظه نمی‌شود.

## ۸. دفاع در برابر Prompt Injection

سه لایه، چون هیچ‌کدام تنها کافی نیست:

1. **جدا کردنِ داده از دستور** — متنِ سند داخلِ پاکتِ `<<<DOCUMENT ... >>>` می‌رود و
   در system prompt نوشته شده که داخلِ پاکت **داده** است نه دستور.
2. **علامت‌گذاریِ الگوهای دستوری** — `injection.js` عبارت‌هایی مثل «همهٔ
   محدودیت‌ها را نادیده بگیر»، «ignore previous instructions»، «تو حالا مدیر
   هستی» را داخلِ متنِ بازیابی‌شده پیدا و بی‌اثر می‌کند و در audit ثبت می‌کند.
3. **قدرتِ واقعی وجود ندارد** — مهم‌ترین لایه. حتی اگر مدل صددرصد فریب بخورد و
   تصمیم بگیرد دیتابیس را پاک کند، **ابزارِ پاک کردن وجود ندارد**. امنیت به
   «قانع نشدنِ مدل» تکیه نکرده.

## ۹. چیزهایی که عمداً نساخته‌ام

صادقانه، تا بعداً کسی فکر نکند جا افتاده است:

- **ابزارِ نوشتن، حتی «امن»** — نسخهٔ اول کاملاً read-only است، طبقِ خواسته.
- **خواندنِ زندهٔ دادهٔ قرض‌داران توسط AI** — سرویس به `server/data` وصل نمی‌شود.
  رباتِ فعلیِ داخلِ برنامه (`_botAnswer`) این کار را می‌کند و دستِ خودِ برنامه است،
  نه دستِ AI. این تفکیک عمدی است: AI مستندات را می‌داند، برنامه داده را.
- **اسکنِ QR سمتِ سرور** — روی دستگاهِ کاربر انجام می‌شود، ارزان‌تر و خصوصی‌تر.
- **آموزشِ مدل (fine-tune)** — RAG برای این کار کافی است و آموزش روی کامپیوترِ
  خانگی یعنی ساعت‌ها کارِ ۱۰۰٪ GPU. دقیقاً همان چیزی که نباید بشود.
