# برنامهٔ ویندوز — مرکز فرمان

همان پنلِ داخلِ همین مخزن، فقط داخلِ یک پنجرهٔ واقعیِ ویندوز:

```
┌────────────────────────────────────────────────────────┐
│ ● مرکز فرمان   آماده · http://127.0.0.1:4700   [دکمه‌ها] │
├────────────────────────────────────────────────────────┤
│                                                         │
│                   خودِ پنل                              │
│                   (تمامِ صفحه — ترمینال بسته است)        │
│                                                         │
└────────────────────────────────────────────────────────┘
```

با زدنِ دکمهٔ **ترمینال** کادرِ خودش پایین باز می‌شود:

```
├──────────────── ▬▬▬ ────────────────────────────────────┤  ← دستگیره
│ ترمینال — خروجی واقعی سرور  [کپی] [پاک] [پنجرهٔ جدا ⧉] [✕]│
│ 08:20:55  ✅ پنل مدیریت سرور خانگی بالا آمد             │
│ 08:20:55  پوشهٔ داده: D:\ControlCenter                  │
└────────────────────────────────────────────────────────┘
```

- آیکن روی دسکتاپ و در منوی Start
- بارِ اول می‌پرسد **اطلاعات کجا ذخیره شود** و نقشهٔ پوشه‌ها را نشان می‌دهد
- ترمینال، خروجیِ واقعیِ سرور است — نه چیزِ تزئینی
- **به نصبِ Node.js نیاز ندارد**؛ Node همراهِ خودِ برنامه می‌آید

### ترمینال مزاحمِ صفحه نمی‌شود

| کار | چطور |
| --- | --- |
| باز و بسته کردن | دکمهٔ **ترمینال** در نوارِ بالا، یا **✕** در خودِ کادر |
| کم و زیاد کردنِ بلندی | **دستگیرهٔ** بالای کادر را با ماوس بکش |
| بردن به پنجرهٔ جداگانه | **پنجرهٔ جدا ⧉** — پنجره‌اش تمام‌صفحه باز می‌شود |
| تمام‌صفحهٔ واقعی | در آن پنجره: دکمهٔ **تمام‌صفحه** یا کلیدِ **F11** |
| برگرداندن به برنامه | در آن پنجره: **برگشت به برنامه** یا کلیدِ **Esc** |

- اولِ کار ترمینال **بسته** است تا کلِ پنجره مالِ خودِ پنل باشد
- انتخابِ شما (باز/بسته و بلندی) یادش می‌ماند و دفعهٔ بعد همان‌طور بالا می‌آید
- اگر سرور بالا نیامد، ترمینال خودش باز می‌شود تا دلیلش را ببینید
- پنجرهٔ جدا همان خروجیِ **زنده** را می‌گیرد، نه یک کپیِ ثابت

## به‌روزرسانی از داخلِ خودِ برنامه

**فایلِ نصبی را فقط یک بار می‌گیرید.** بعد از آن، به‌روزرسانی از داخلِ برنامه
انجام می‌شود: صفحهٔ **به‌روزرسانی** در خودِ پنل → **بررسی** → **نصب**.

دانلودش **چند صد کیلوبایت** است، نه ۸۵ مگابایت — چون فقط خودِ کدِ برنامه از
GitHub می‌آید، نه Electron و Node که همراهِ نصب هستند و عوض نمی‌شوند.

بعد از نصب، برنامه یک نوارِ سبز نشان می‌دهد: **باز کردن دوبارهٔ برنامه**.
با یک کلیک برنامه بسته و باز می‌شود و نسخهٔ تازه بالا می‌آید.

### چه چیزی به‌روز می‌شود

| بخش | از داخلِ برنامه؟ |
| --- | --- |
| سرور و پنل (`resources/server`) | بله |
| پوستهٔ برنامه: پنجره، ترمینال، صفحهٔ بارِ اول | بله |
| Electron و Node که برنامه رویشان می‌چرخد | نه — فایلِ نصبیِ تازه لازم است |
| کتابخانه‌های تازهٔ سرور | نه — همان‌جا می‌گوید و **هیچ فایلی را دست نمی‌زند** |

### اگر به‌روزرسانی خراب بود

نسخهٔ تازه در پوشهٔ جدا می‌نشیند، نه روی نصب. اگر بالا نیاید، برنامه خودش
برمی‌گردد به نسخهٔ همراهِ نصب و نسخهٔ خراب را کنار می‌گذارد. یعنی یک
به‌روزرسانیِ خراب برنامه را از کار نمی‌اندازد. (`test/overlay.mjs` دقیقاً همین
را امتحان می‌کند: یک نسخهٔ عمداً خراب می‌گذارد و می‌سنجد که برنامه بالا می‌آید.)

بکاپِ نصبِ قبلی هم قبل از هر به‌روزرسانی گرفته می‌شود و دکمهٔ **برگشت** در
صفحهٔ به‌روزرسانی هست.

## گرفتنِ فایلِ نصبی

**راهِ ساده:** از بخشِ [Releases](https://github.com/vil3ntec-it/server/releases) فایل
`ControlCenter-Setup-<نسخه>.exe` را بگیر و اجرا کن. موقعِ نصب می‌پرسد
**کجا نصب شود**.

**اگر هنوز Release نساخته‌ای:** در GitHub → زبانهٔ **Actions** → آخرین اجرای
«برنامه ویندوز» → پایینِ صفحه، بخشِ **Artifacts** → `ControlCenter-Setup`.

این گردشِ کار خودش با هر تغییرِ برنامه اجرا می‌شود، پس معمولاً یک فایلِ تازه
آنجا هست. برای ساختنِ Release هم کافی است یک تگ بزنی:

```bash
git tag v1.1.0 && git push origin v1.1.0
```

## اجرا از روی کد (برای توسعه)

```bash
cd homelab-panel/server && npm install          # وابستگی‌های سرور
cd ../web && npm install && npm run build       # ساختِ رابط کاربری
cd ../desktop && npm install && npm start       # اجرای برنامه
```

## ساختِ فایلِ نصبی روی ویندوزِ خودت

```powershell
cd homelab-panel\desktop
npm install
npm run build:win
```

خروجی در `desktop\dist\ControlCenter-Setup-<نسخه>.exe`.

## آزمون

```bash
cd homelab-panel/desktop && npm test
```

برنامه واقعاً بالا می‌آید، پوشه انتخاب می‌شود، سرور اجرا می‌شود و بررسی
می‌شود که ترمینال خروجیِ واقعی دارد و پنل داخلِ پنجره بار شده.

## اطلاعات کجا می‌رود؟

هرجا که بارِ اول انتخاب کنی. پیش‌فرضِ پیشنهادی `Documents\ControlCenter` است.
هر وقت خواستی ببینی‌اش، دکمهٔ **پوشهٔ اطلاعات** در نوارِ بالا آن را باز می‌کند.

```
<پوشهٔ انتخابی>\
├── panel.db          دیتابیس پنل
├── Projects\         پوشهٔ هر پروژه
│   └── <نام پروژه>\
│       ├── app\  config\  data\
│       ├── backups\    بکاپ‌ها
│       ├── logs\       لاگ‌ها
│       └── releases\   فایل‌های منتشرشده
├── vault.key         کلید گاوصندوق — با اولین راز ساخته می‌شود
└── updates\          بستهٔ به‌روزرسانی‌ها
```

> ⚠️ از `vault.key` بکاپ بگیر. بدونِ آن، رازهای گاوصندوق باز نمی‌شوند.

**جای نصبِ خودِ برنامه** (کدها) با **جای اطلاعات** یکی نیست — و همین خوب است:
با حذف یا به‌روزرسانیِ برنامه، اطلاعاتت دست نمی‌خورد.

## چطور کار می‌کند

| بخش | چه می‌کند |
| --- | --- |
| `main.js` | راه‌اندازِ کوچک: تصمیم می‌گیرد نسخهٔ همراهِ نصب اجرا شود یا نسخهٔ به‌روزرسانی‌شده، و اگر دومی بالا نیامد برمی‌گردد به اولی |
| `app/main-impl.js` | سرور را با Node ی که همراهِ Electron است اجرا می‌کند، خروجی‌اش را می‌گیرد، منتظرِ `/health` می‌ماند و بعد پنجره را به پنل وصل می‌کند |
| `app/preload.cjs` | پلِ امن؛ فقط همان چند کارِ لازم از رابط کاربری قابلِ صدا زدن است |
| `app/shell.html/css/js` | نوارِ بالا، صفحهٔ بارِ اول، و کادرِ ترمینال |
| `app/terminal.html/js` | ترمینال وقتی در پنجرهٔ خودش باز می‌شود؛ همان جریانِ زندهٔ لاگ را می‌گیرد |

نکته‌های امنیتی: `contextIsolation` روشن، `nodeIntegration` خاموش، CSP سخت‌گیرانه
روی خودِ پوسته، و پیوندهای بیرونی در مرورگرِ سیستم باز می‌شوند نه داخلِ برنامه.

## برنامهٔ سرور خانگی (پنجرهٔ ویندوزی) — قابلیت‌های اتصالِ برنامه‌ها

نسخهٔ **1.2.0**

یک برنامهٔ ویندوزیِ واقعی برای کارهای روزمرهٔ سرور — نه مرورگر، نه WebView.
با **WPF** ساخته شده (همان چیزی که برنامه‌های امروزیِ ویندوز با آن ساخته
می‌شوند): تمام‌صفحه، تمِ تیره، گوشه‌های گرد، خطِ **وزیرمتن** و منوی کناری.
هیچ چیزی هم لازم نیست نصب شود — PowerShell و WPF از خودِ ویندوزند.

## نصب

**یک فایل، همین.** روی `نصب-برنامه.bat` دوبار کلیک کنید — کلِ برنامه داخلِ
همان یک فایل است (خودش باز می‌شود، چیزی برای اکسترکت کردن ندارید). یک
نصب‌کنندهٔ معمولی باز می‌شود:

1. **خوش‌آمد** — می‌گوید برنامه چه کار می‌کند
2. **انتخابِ پوشه** — پیش‌فرض `C:\Users\<شما>\PumpServer`؛ با دکمهٔ «انتخابِ پوشه»
   هر جای دیگری هم می‌شود. گزینه‌ها: میان‌برِ دسکتاپ، منوی استارت،
   نصبِ وابستگی‌ها، و اجرای برنامه بعد از نصب
3. **نصب** — فایل‌ها کپی می‌شوند و خروجیِ `npm install` **داخلِ خودِ پنجره**
   دیده می‌شود (نه در پنجرهٔ سیاه)
4. **پایان**

اگر همان پوشه‌ای را بدهید که قبلاً نصب کرده‌اید، به‌روزرسانی می‌شود و پوشهٔ
`data` و فایل `.env` دست نمی‌خورند.

بعد از نصب، از **میان‌برِ روی دسکتاپ** بازش کنید — آن راه اصلاً پنجرهٔ سیاه ندارد.

## هیچ ترمینالی باز نمی‌شود

سرور بدونِ هیچ پنجره‌ای اجرا می‌شود و همهٔ خروجی‌اش در تبِ **«ترمینالِ سرور»**
داخلِ خودِ برنامه، زنده دیده می‌شود — همان چیزی که قبلاً در پنجرهٔ سیاه بود.
با دکمهٔ «روشن کردنِ سرور» خودش همان تب را باز می‌کند تا ببینید چه خبر است.

## چه کار می‌کند

منوی کنارِ پنجره، هفت صفحه:

| صفحه | کار |
|------|-----|
| **خانه** | آدرسِ سرور در یک کادرِ بزرگ با دکمهٔ کپی · سه کادرِ «اندروید / سایت / کامپیوتری» با شمارِ زنده · وضعیتِ پیامک، ایمیل، تونل و دستیار · کاربران، آنلاین‌ها و کدهای امروز |
| **برنامه‌ها و سایت‌ها** | فهرست با فیلترِ نوع، ساختن/حذف/کلیدِ تازه، و کارتِ آماده‌ٔ آدرس‌های API برای دادن به سازندهٔ هر برنامه |
| **ورود با کد (OTP)** | کد بفرست، تأیید کن، و ببین چند میلی‌ثانیه طول کشید |
| **سایت‌های روی سرور** | همان فهرستی که در پنلِ مدیریت بود — بدونِ باز کردنِ مرورگر |
| **تنظیمات** | جی‌میل، سرویسِ پیامک، و روشن/خاموشِ دستیارِ هوش مصنوعی |
| **ترمینالِ سرور** | خروجیِ زندهٔ سرور، با ظاهرِ کنسول |
| **به‌روزرسانی** | گرفتنِ نسخهٔ تازه از GitHub |

روی هر کدام از سه کادرِ صفحهٔ خانه که بزنید، مستقیم می‌رود به فهرستِ همان نوع.

پایینِ منوی کنار همیشه معلوم است سرور روشن است یا خاموش، و با یک دکمه عوض می‌شود.

## یک آدرس برای همهٔ دستگاه‌ها

آدرسی که در صفحهٔ خانه می‌بینید همان یک آدرس است که به همهٔ برنامه‌هایتان
می‌دهید. هر کاربری با شماره یا ایمیلِ خودش وارد شود، **روی هر دستگاهی همان
اطلاعاتِ حسابِ خودش را می‌بیند** — چون داده روی همین سرور می‌ماند، نه روی گوشی.

## به‌روزرسانی از داخلِ برنامه

تبِ «به‌روزرسانی» → «بررسیِ نسخهٔ تازه» → اگر نسخهٔ جدیدی بود، «به‌روزرسانی کن».

برنامه **خودش هم** هر بار که باز می‌شود بررسی می‌کند؛ اگر نسخهٔ تازه‌ای باشد،
بالای پنجره خبر می‌دهد و کنارِ نامِ تب یک نقطه می‌گذارد. (این را می‌شود خاموش کرد.)

نامِ شاخه یادش می‌ماند — یک بار بنویسید، دفعهٔ بعد خودش همان را می‌زند.

ترتیبِ کار:

1. از کدِ فعلی پشتیبان می‌گیرد → `homelab-panel\server\data\backups\code-<تاریخ>`
   (سه پشتیبانِ آخر می‌ماند، قدیمی‌ترها خودشان پاک می‌شوند)
2. نسخهٔ تازه را از GitHub می‌گیرد و باز می‌کند
3. سرور را خاموش می‌کند، فایل‌ها را عوض می‌کند، `npm install` می‌زند
4. سرور را دوباره روشن می‌کند

**هرگز پاک نمی‌شود:** پوشهٔ `data` (دیتابیس، کاربران، لاگ) و فایل `.env` (رمزها).

فیلدِ «شاخه» به‌صورت پیش‌فرض `main` است. اگر تغییرات هنوز در شاخهٔ دیگری است،
نامِ همان شاخه را بنویسید.

## فایل‌ها

| فایل | چیست |
|------|------|
| `..\..\نصب-برنامه.bat` | نصب‌کننده (در ریشهٔ پروژه) |
| `install.ps1` | پنجرهٔ نصب |
| `برنامه-سرور.bat` | اجرای برنامه بدونِ نصب |
| `launch.vbs` | همان اجرا، ولی بدونِ حتی یک لحظه پنجرهٔ سیاه (میان‌برها به این وصل‌اند) |
| `app.ps1` | خودِ پنجرهٔ برنامه (WinForms) |
| `lib.ps1` | مغزِ کار: .env، روشن/خاموش، ترمینال، API، به‌روزرسانی، نصب |
| `عیب‌یابی.bat` | اجرای برنامه با نمایشِ خطاها |
| `test/lib.tests.ps1` | آزمونِ مغز — بدونِ باز شدنِ پنجره |

اجرای آزمون:

```
powershell -NoProfile -ExecutionPolicy Bypass -File test\lib.tests.ps1
```

## اگر باز نشد (یا باز شد و گم شد)

برنامه بدونِ پنجرهٔ سیاه اجرا می‌شود، پس خطاها جایی دیده نمی‌شدند. حالا:

* هر خطا در `homelab-panel\server\data\desktop-error.log` نوشته می‌شود
* اگر پنجره بی‌درنگ بسته شود، خودش یک پیام نشان می‌دهد و مسیرِ گزارش را می‌گوید
* اگر بخشی از برنامه بالا نیاید، بقیه کار می‌کند و بالای پنجره می‌نویسد کدام بخش

برای دیدنِ زندهٔ خطا:

| مشکل | فایلی که باید بزنید |
|------|---------------------|
| نصب‌کننده باز نمی‌شود | `اگر-باز-نشد.bat` (در ریشهٔ پروژه) |
| خودِ برنامه باز نمی‌شود | `عیب‌یابی.bat` (کنارِ `app.ps1`) |

هر دو با پنجرهٔ سیاه و بدونِ مخفی‌کاری اجرا می‌کنند و آخرش می‌ایستند تا خطا را
بخوانید یا از آن عکس بگیرید.

* **می‌گوید اجرای اسکریپت ممنوع است:** خودِ `برنامه-سرور.bat` و میان‌برها این را
  دور می‌زنند (`-ExecutionPolicy Bypass`)؛ از همان‌ها بازش کنید.
* **سرور روشن نمی‌شود:** Node.js نصب است؟ تبِ «ترمینالِ سرور» علتش را می‌گوید.

لینوکس ندارد؛ آن‌جا همان صفحهٔ `http://localhost:4700/connect` را باز کنید.
