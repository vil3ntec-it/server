# Agent سرور

یک برنامهٔ کوچک که روی سرورهای **دیگر** (VPS، اختصاصی، ابری) اجرا می‌شود و
وضعیتِ واقعیِ آن ماشین را برای مرکز فرمان می‌فرستد.

- بدونِ هیچ وابستگیِ npm — فقط خودِ Node (نسخهٔ ۲۰ به بالا)
- هیچ درگاهی باز نمی‌کند
- **هیچ راهی برای اجرای دستور از راه دور ندارد**

> سرورِ خانگی (همان کامپیوتری که پنل رویش است) به Agent نیاز ندارد؛ پنل
> اطلاعاتش را مستقیم می‌خواند.

---

## راه‌اندازی

### ۱) در پنل کلید بسازید

**مرکز فرمان → سرورها → سرورِ موردنظر → Agent → ساخت کلید**

کلید **فقط همان یک‌بار** نشان داده می‌شود. کپی‌اش کنید.

### ۲) این پوشه را روی سرورِ مقصد ببرید

```bash
scp -r homelab-panel/agent root@1.2.3.4:/opt/control-center-agent
```

### ۳) تنظیمات

```bash
cd /opt/control-center-agent
cp agent.env.example agent.env
nano agent.env
```

سه مقدار حتماً لازم است:

```bash
CC_PANEL_URL=https://panel.example.com
CC_SERVER_ID=srv_1a2b3c4d
CC_AGENT_KEY=<کلیدی که پنل نشان داد>
```

### ۴) اجرا

```bash
./start-agent.sh          # لینوکس / مک
start-agent.bat           # ویندوز
```

### ۵) همیشه روشن (لینوکس)

```bash
sudo cp control-center-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now control-center-agent
sudo systemctl status control-center-agent
```

## همهٔ تنظیمات

| متغیر | چیست | پیش‌فرض |
| --- | --- | --- |
| `CC_PANEL_URL` | آدرس مرکز فرمان | — (لازم) |
| `CC_SERVER_ID` | شناسهٔ سرور (`srv_…`) | — (لازم) |
| `CC_AGENT_KEY` | کلیدی که پنل یک‌بار نشان داد | — (لازم) |
| `CC_INTERVAL` | فاصلهٔ گزارش (ثانیه) | `30` |
| `CC_SERVICES` | سرویس‌هایی که بازبودنشان سنجیده شود: `نام:پورت[:میزبان]` | — |
| `CC_HEALTH_HTTP` | آدرسی که Agent از داخلِ سرور بسنجد | — |
| `CC_HEALTH_WS` | آدرسِ WebSocket برای دست‌دادنِ واقعی | — |
| `CC_TUNNEL_PORT` | پورتِ محلیِ تونل، برای سنجشِ سلامتش | — |
| `CC_VERBOSE` | `1` تا هر گزارش را در ترمینال چاپ کند | `0` |
| `CC_INSECURE` | `1` اگر پنل گواهیِ خودامضا دارد (فقط شبکهٔ داخلی) | `0` |

نمونه:

```bash
CC_SERVICES=api:3000,websocket:4701,postgres:5432
CC_HEALTH_HTTP=http://127.0.0.1:3000/health
CC_HEALTH_WS=ws://127.0.0.1:4701
```

## چه چیزی فرستاده می‌شود

```
سیستم‌عامل، نامِ ماشین، معماری، مدتِ روشن بودن
پردازنده: درصدِ مصرف، تعدادِ هسته، مدل، بارِ متوسط
حافظه: کل، آزاد، مصرف‌شده، درصد
دیسک‌ها: مسیر، کل، آزاد، درصد
شبکه: آدرس‌ها، سرعتِ لحظه‌ایِ دریافت و ارسال
نسخه‌ها: Node.js، PostgreSQL، Docker، Nginx
سرویس‌ها: هر کدام باز است یا نه، با زمانِ پاسخ
سلامت: نتیجهٔ واقعیِ HTTP و WebSocket و تونل
```

هیچ فایل، رمز یا محتوایی از سرور فرستاده نمی‌شود.

## امنیت

هر گزارش این‌طور امضا می‌شود:

```
signature = HMAC-SHA256( کلید ,  "<مهر زمانی>.<بدنهٔ JSON>" )
```

- خودِ کلید هرگز روی شبکه نمی‌رود.
- سرور مهرِ زمانی را می‌سنجد (پنجرهٔ ۵ دقیقه)، پس گزارشِ ضبط‌شده دوباره
  پذیرفته نمی‌شود.
- کلید در سمتِ پنل رمزنگاری‌شده در گاوصندوق می‌ماند.
- اگر کلید را در پنل باطل کنید، همان لحظه گزارش‌ها رد می‌شوند.

---

## عیب‌یابی

**«پنل گزارش را نپذیرفت (۴۰۱)»**
کلید یا شناسهٔ سرور اشتباه است، یا کلید در پنل باطل شده. کلیدِ تازه بسازید.

**«timestamp_out_of_range»**
ساعتِ این سرور با ساعتِ پنل بیش از ۵ دقیقه فرق دارد. `ntp` را روشن کنید:

```bash
sudo timedatectl set-ntp true
```

**«ارسالِ گزارش ناموفق بود»**
سرور به `CC_PANEL_URL` نمی‌رسد. با `curl -v $CC_PANEL_URL/health` امتحان کنید.
