# پنل مدیریت سرور خانگی

یک داشبورد واقعی برای مدیریت سرور خانگی: وضعیت لحظه‌ای سخت‌افزار، مدیریت سایت‌ها،
دامنه‌ها، فایل‌ها و لاگ‌ها. **هیچ دادهٔ نمونه یا دمویی در کار نیست** — همه‌چیز از خودِ
سیستم‌عامل و فایل‌های واقعی روی همان کامپیوتر خوانده می‌شود.

این پروژه کاملاً **جدا از سایتِ پمپ یعقوبی** است و هیچ فایلی از سایت را تغییر نمی‌دهد.
تنها نقطهٔ اشتراک، سرورِ همان سایت است که — به درخواست شما — داخل همین پنل و روی
**همان پورت** اجرا می‌شود (بخش «سرور سایت» را ببینید).

---

## فناوری‌ها

| بخش | فناوری |
|-----|--------|
| Backend | Node.js + **Express** |
| اطلاعات لحظه‌ای | **Socket.IO** |
| دیتابیس | **SQLite** (ماژول داخلی `node:sqlite` — بدون کامپایل و بدون نصب جداگانه) |
| Frontend | **React + TypeScript** (Vite) |
| ظاهر | **Tailwind CSS** + آیکون‌های Lucide |
| امنیت | **JWT** + رمز عبورِ هش‌شده با **scrypt** + نشست‌ها |

خروجی build رابط کاربری داخل `server/public` است و همراه ریپو ذخیره می‌شود، پس روی سرور
خانگی **هیچ ابزار build لازم نیست**.

---

## اجرا

فقط **Node.js نسخهٔ ۲۲ یا بالاتر** لازم است.

**لینوکس / مک:**
```bash
cd homelab-panel/server
./start-linux.sh
```

**ویندوز:** روی `start-windows.bat` دوبار کلیک کنید.

بار اول وابستگی‌ها خودکار نصب می‌شوند (به اینترنت نیاز دارد؛ فقط همان یک‌بار).
بعد از بالا آمدن، آدرس‌ها چاپ می‌شوند:

```
پنل روی این کامپیوتر:   http://localhost:4700
از شبکهٔ خانگی:          http://192.168.1.20:4700
```

بار اول یک **نام کاربری و رمز عبور مدیر** می‌سازید؛ دفعات بعد با همان وارد می‌شوید.

### همیشه روشن — بدون ترمینالِ باز

راه‌اندازهای بالا تا وقتی پنجرهٔ ترمینال باز است کار می‌کنند. برای این که سرور
**با بستنِ ترمینال خاموش نشود** و **با روشن شدنِ کامپیوتر خودش بالا بیاید**:

**ویندوز:** روی `service-windows.bat` دوبار کلیک کنید.

**لینوکس / مک:**
```bash
cd homelab-panel/server
./service-linux.sh install
```

بعد از آن، پنجره را ببندید — سرور به کارش ادامه می‌دهد. دستورهای دیگر:

```bash
./service-linux.sh status     # بالاست یا نه
./service-linux.sh stop       # توقف
./service-linux.sh restart    # راه‌اندازی مجدد
./service-linux.sh logs       # لاگ زنده
./service-linux.sh uninstall  # حذف از راه‌اندازی خودکار
```

روی ویندوز همین‌ها با `service-windows.bat start|stop|status|uninstall` است.

پشتِ صحنه: روی لینوکس یک سرویسِ کاربری systemd ساخته می‌شود (`Restart=always`، و
`loginctl enable-linger` تا بدون ورود کاربر هم بالا بماند)؛ اگر systemd نبود، با
`setsid nohup` پروسه از ترمینال جدا می‌شود. روی ویندوز یک Scheduled Task در حالت
«ورود به سیستم» ثبت می‌شود که پنل را با `run-hidden.vbs` **کاملاً بی‌پنجره** اجرا
می‌کند. هیچ‌کدام به دسترسی مدیر نیاز ندارند.

وقتی پنجره‌ای در کار نیست، خروجی در `data/panel.log` می‌نشیند و شمارهٔ پروسه در
`data/panel.pid` نگه داشته می‌شود (برای `stop` و `status`).

## سرورِ سایت — روی همان آدرس و همان پورت

سرور شخصیِ برنامهٔ پمپ یعقوبی (همان جایگزین فایربیس) داخل همین پنل اجرا می‌شود.
یعنی **آدرس خودِ پنل** در سایت هم پذیرفته می‌شود و لازم نیست دو برنامهٔ جدا روشن باشد.

در پنل به صفحهٔ **«سرور سایت»** بروید. آنجا دقیقاً همان دو چیزی که سایت می‌خواهد را
پیدا می‌کنید:

- **آدرس سرور:** `ws://192.168.1.20:4700` (کپی با یک کلیک)
- **رمز سرور:** با دکمهٔ «نمایش رمز» دیده می‌شود و قابل کپی است

این دو را در خودِ سایت وارد کنید: **تنظیمات ← هم‌زمان‌سازی ← سرور شخصی**.

> پروتکل ذره‌ای تغییر نکرده؛ سایت بدون هیچ دست‌کاری با آن کار می‌کند.
> `http://<آدرس>:4700/health` هم مثل قبل پاسخ می‌دهد.
>
> در همان صفحه، شاخه‌های داده، تعداد اتصال‌های زنده و تعداد خواندن/نوشتن هم دیده می‌شود
> و می‌توانید رمز را عوض کنید.

اگر نمی‌خواهید سرورِ سایت روی پنل باشد، در `.env` بگذارید `HLP_SITESYNC=0`.

### اتصال از اینترنت — خودکار

آدرس `ws://192.168.x.x` **فقط داخل خانه** کار می‌کند: آی‌پی خانگی از بیرون پیدا
نمی‌شود، و صفحه‌ای که با `https` باز شده هم طبق قانون مرورگر حق ندارد به `ws://`
وصل شود.

پنل خودش این را حل می‌کند. **هیچ کاری لازم نیست**: هنگام بالا آمدن، ابزار رسمی
Cloudflare (`cloudflared`) را یک‌بار دانلود می‌کند و یک تونل رایگان می‌سازد. بعد در
صفحهٔ «سرور سایت» این‌ها را می‌بینید:

- **لینک یک‌کلیکی** مثل
  `https://yaqobipump.top/?server=wss://xxxx.trycloudflare.com&token=…`
- همان لینک به‌صورت **QR** برای اسکن با گوشی

هر دستگاهی این لینک را باز کند (یا QR را اسکن کند)، سایت خودش را به همین سرور وصل
می‌کند و از آن به بعد همهٔ دستگاه‌ها **یک دادهٔ مشترک** می‌بینند — بدون وارد کردن
دستی آدرس و رمز.

> آدرس تونل رایگان با هر بار خاموش/روشن شدن سرور عوض می‌شود؛ آن وقت فقط دوباره
> لینک تازه را از همان صفحه بردارید. (برای آدرس ثابت باید تونل نام‌دار با حساب
> Cloudflare ساخت.)

**امنیت:** تونل همیشه روی **پورت ۴۷۰۱** باز می‌شود که فقط سرورِ سایت را سرو می‌کند —
بدون پنل، بدون API و بدون فایل‌منیجر. پنل (پورت ۴۷۰۰) هرگز روی اینترنت نمی‌رود.

برای خاموش کردن تونل: دکمه‌اش در همان صفحه، یا `HLP_TUNNEL=0` در `.env`.

### آدرس ثابت — همان مدل فایربیس

تونل رایگانِ سریع هر بار آدرس تازه می‌دهد، پس نمی‌شود آن را یک‌بار در سایت نوشت.
اگر دامنه‌تان روی **Cloudflare** باشد، پنل می‌تواند یک **آدرس ثابت و همیشگی**
بسازد (مثل `sync.example.com`). آن وقت:

> آدرس **یک‌بار** در سایت می‌نشیند و از آن به بعد **هر کسی سایت را باز کند،
> خودکار به همین سرور وصل می‌شود** — بدون لینک، بدون QR، بدون وارد کردن رمز.
> دقیقاً همان کاری که فایربیس می‌کرد.

راه‌اندازی یک‌بار است، در صفحهٔ «سرور سایت» ← بخش **«آدرس ثابت»**:

1. **ورود به Cloudflare** — دکمه را بزنید؛ یک آدرس می‌آید، در مرورگر بازش کنید و
   دامنه‌تان را تایید کنید.
2. **زیردامنه را بنویسید** (مثلاً `sync.example.com`) و «ساخت آدرس ثابت» را بزنید.
   پنل خودش تونل را می‌سازد، رکورد DNS را می‌زند و تونل را با همان آدرس بالا می‌آورد.
3. پنل دو خط آماده به شما می‌دهد؛ آن‌ها را در `index.html` سایت جایگزین کنید:

```js
var SELF_HOST_URL   = 'wss://sync.example.com';
var SELF_HOST_TOKEN = '<رمز سرور>';
```

تمام. از این به بعد سایت مثل قبل کار می‌کند، فقط بک‌اندش سرور خودتان است.

> ⚠️ رمز سرور داخل فایل سایت قابل دیدن است (همان‌طور که در نسخهٔ قبلی هم بود).
> یعنی هر کسی سایت را باز کند به دادهٔ مشترک دسترسی دارد — همان مدل فایربیسِ باز.
> اگر بعداً خواستید دسترسی محدود شود، باید لایهٔ کاربر/رمز به خودِ سایت اضافه شود.

## چه چیزهایی دارد

### داشبورد
نام سرور، IP داخلی، IP عمومی، وضعیت آنلاین، مصرف CPU / RAM / دیسک، سرعت دانلود و آپلود
شبکه، دمای سیستم (اگر سخت‌افزار پشتیبانی کند)، مدت روشن بودن سرور، تعداد سایت‌ها و
دامنه‌ها، و آخرین خطاها. همه‌چیز هر ۲ ثانیه زنده بروز می‌شود (بدون Refresh).

### سایت‌ها
- **کشف خودکار:** پوشه‌های استاندارد سرور اسکن می‌شوند (`/sites`، `/var/www`،
  `/srv/www`، `htdocs`، `laragon\www`، `inetpub\wwwroot`، …) و نوع پروژه از روی فایل‌های
  واقعی تشخیص داده می‌شود (Node.js، Next.js، Laravel، Django، WordPress، PHP، استاتیک).
- **افزودن دستی:** فقط مسیر پروژه را می‌دهید (`/home/server/shop` یا `D:\Sites\MyStore`).
- برای هر سایت: نام، دامنه، مسیر، وضعیت آنلاین/آفلاین (تست واقعی پورت)، پورت،
  حجم فایل‌ها و آخرین زمان بروزرسانی.
- روی هر کارت: **Open / Start / Stop / Restart / Logs / Settings**.
- سایت‌های استاتیک با سرور فایلِ داخلی پنل اجرا می‌شوند؛ بقیه با دستور اجرای خودشان.

### پوشهٔ جدا برای هر سایت
هر سایت پوشهٔ مستقل خودش را دارد (`/sites/shop`، `/sites/blog`، …) و علاوه بر آن یک
فضای کاری اختصاصی در پوشهٔ دادهٔ پنل:

```
data/sites/<نام سایت>/
├── config.json    تنظیمات و متغیرهای محیطی همان سایت
├── logs/          لاگ اختصاصی
├── backups/       بکاپ اختصاصی
└── db/            دیتابیس اختصاصی
```

مسیر این پوشه‌ها به‌صورت متغیر محیطی (`SITE_DATA_DIR`، `SITE_DB_DIR`، `SITE_LOG_DIR`،
`SITE_BACKUP_DIR`) به پروسهٔ هر سایت داده می‌شود، پس **هیچ چیزی بین سایت‌ها مشترک نیست**.

### افزودن سایت — همه‌چیزش خودکار
کافی است سایت را اضافه کنید؛ بقیه‌اش خودش انجام می‌شود:

| چیزی که خودکار می‌شود | کجا می‌نشیند |
| --- | --- |
| پوشهٔ فضای کاری | `data/sites/<نام سایت>/` |
| پوشهٔ دادهٔ اختصاصی + رمزِ جدا | `data/site-sync/sites/<نام سایت>/` |
| پورت آزاد | خودکار از بازهٔ ۸۱۰۰ به بالا |
| دامنه | زیردامنهٔ خودش از «دامنهٔ پایه» (مثلاً `shop.yaqobipump.top`) |
| آدرس اینترنتی | اگر دامنهٔ پایه نگذاشته باشید، تونلِ مستقلِ خودِ سایت |

«دامنهٔ پایه» را یک‌بار در **تنظیمات** بگذارید (اگر آدرس ثابتِ تونل را تنظیم کرده
باشید، خودش حدس زده می‌شود). اگر سایتِ هم‌نام دیگری همان زیردامنه را گرفته باشد،
زیردامنهٔ آزادِ بعدی انتخاب می‌شود تا دامنهٔ کسی دزدیده نشود.

اگر این رفتار را نمی‌خواهید، در تنظیمات تیکِ «راه‌اندازی خودکار سایت تازه» را
بردارید.

### پوشهٔ دادهٔ جدا برای هر سایت (سرورِ داده)
سرورِ داده هم برای هر سایت یک «دفترِ» مستقل نگه می‌دارد، با پوشه و **رمز جداگانه**:

```
data/site-sync/                  دفترِ اصلی (سایت پمپ یعقوبی — مثل قبل)
└── sites/
    ├── shop/
    │   ├── token.txt            رمزِ مخصوص همین سایت
    │   └── <شاخه>.json          دادهٔ همین سایت
    └── blog/
        ├── token.txt
        └── <شاخه>.json
```

هر سایت با آدرس خودش وصل می‌شود:

```
wss://<آدرس سرور>/?site=<نام سایت>&token=<رمزِ همان سایت>
```

اگر `?site=` نفرستد هم از روی رمز پیدا می‌شود، پس سایت‌های قدیمی بدون هیچ تغییری کار
می‌کنند. رمزِ یک سایت روی پوشهٔ سایت دیگر کار نمی‌کند، پس **دادهٔ سایت‌ها نه قاطی
می‌شود و نه گم**. آدرس و رمزِ هر سایت در «سایت‌ها ← تنظیمات ← پوشهٔ دادهٔ اختصاصی»
است.

### آدرس اینترنتی برای هر سایت
هر سایت — جدا از بقیه — می‌تواند آدرس `https` مستقلِ خودش را بگیرد. در کارت هر سایت
دکمهٔ «گرفتن آدرس اینترنتی» یک تونل مخصوص همان پورت بالا می‌آورد:

```
سایت A (پورت 8100) → https://xxxx.trycloudflare.com
سایت B (پورت 8101) → https://yyyy.trycloudflare.com
```

اگر دامنهٔ خودتان را به سایت وصل کرده باشید، آدرس ثابتِ همان دامنه از راه تونلِ
نام‌دار می‌آید و به تونل سریع نیازی نیست.

### دامنه‌ها
وضعیت DNS (رکورد A/CNAME/NS واقعی)، گواهی SSL (صادرکننده و تاریخ انقضای واقعی از خود
گواهی)، تاریخ انقضای ثبت دامنه (WHOIS واقعی روی پورت ۴۳)، سایت متصل و وضعیت آنلاین.

هر سایت می‌تواند **چند دامنه** داشته باشد، و هر دامنه هر وقت بخواهید به **سایت دیگری**
منتقل می‌شود: در جدول دامنه‌ها فقط «سایت متصل» را عوض کنید. مسیرهای تونل خودکار
بازنویسی می‌شوند، پس همان دامنه از آن لحظه به سایت تازه می‌رود. نامِ خودِ دامنه هم با
دکمهٔ ویرایش عوض می‌شود، بدون این که اتصالش به سایت از دست برود.

**دامنه‌های قُرق:** پنل برای هر دامنه دستور `cloudflared tunnel route dns --overwrite-dns`
را می‌زند و این دستور رکورد DNS موجود را بی‌سوال بازنویسی می‌کند. اگر آن رکورد، رکورد
سایتِ عمومیِ ما روی GitHub Pages باشد (`yaqobipump.top`)، هم سایت می‌خوابد و هم گیت‌هاب
گواهی https آن را برمی‌دارد و مرورگر `ERR_CERT_COMMON_NAME_INVALID` می‌دهد. پس این
دامنه‌ها ثبت و بررسی می‌شوند ولی **هرگز به تونل نمی‌روند** — فقط خودِ دامنه، نه
زیردامنه‌هایش (`shop.yaqobipump.top` آزاد است). فهرست را با تنظیمِ `protected_domains`
یا متغیرِ محیطیِ `HLP_PROTECTED_DOMAINS` (با کاما جدا؛ خالی یعنی هیچ قُرقی) عوض کنید.

### آنلاین یا آفلاین — جوابِ درست
وضعیت هر سایت با سه بررسی پشت سر هم مشخص می‌شود و اولین جوابِ مثبت کافی است:

1. پروسه‌ای که خودِ پنل اجرا کرده زنده است؟
2. پورتِ محلیِ سایت جواب می‌دهد؟
3. دامنه/آدرس عمومیِ سایت از اینترنت جواب می‌دهد؟

برای همین سایتی که روی هاست دیگری یا از راه تونل بالاست دیگر «آفلاین» نشان داده
نمی‌شود. زیر وضعیت هم نوشته می‌شود از کدام راه آنلاین تشخیص داده شده.

### فایل‌منیجر
آپلود، دانلود، تغییر نام، حذف، ساخت پوشه، ویرایش فایل، کپی، انتقال و جستجو —
همه روی فایل‌های واقعی. برای امنیت، فقط داخل «ریشه‌های مجاز» کار می‌کند
(ریشهٔ سایت‌ها، پوشهٔ هر سایت، و هر مسیری که خودتان در تنظیمات اضافه کنید).

### مانیتورینگ
نمودار زندهٔ CPU (به‌همراه هر هسته)، RAM، دیسک (هر پارتیشن) و شبکه — بدون Refresh.

### لاگ‌ها
هر سایت لاگ جدای خودش را دارد (خطا / هشدار / درخواست) که زنده هم بروز می‌شود،
به‌علاوهٔ لاگ سراسری خود پنل.

### تنظیمات
نام سرور، لوگو، پوستهٔ تیره/روشن/سیستم، و زبان: **فارسی، انگلیسی، عربی، پشتو**
(چیدمان راست‌به‌چپ و چپ‌به‌راست خودکار).

### اعلان‌ها (جایگزینِ ntfy، روی سرور خودتان)
هر برنامه‌ای که بتواند یک درخواست ساده بزند، می‌تواند خبر بدهد و آن خبر روی
برنامهٔ **تانک تیل یعقوبی** می‌نشیند — حتی وقتی برنامه بسته یا گوشی قفل است:

```bash
# ساده‌ترین حالت
curl -d "تیل مخزن ۲ کم شد"  https://sync.yaqobipump.top/api/notify/pump

# با عنوان، اولویت (۱ تا ۵) و برچسب
curl -H "X-Title: %D9%87%D8%B4%D8%AF%D8%A7%D8%B1" -H "X-Priority: 5" \
     -H "X-Tags: fuel,urgent" -d "مخزن خالی شد" .../api/notify/pump

# همان چیز با JSON — برای متنِ فارسی راحت‌تر است
curl -H "Content-Type: application/json" \
     -d '{"title":"هشدار","message":"مخزن خالی شد","tags":["fuel"]}' .../api/notify/pump
```

- **«موضوع» جای حساب کاربری را می‌گیرد**: هر کس نام موضوع را بداند خبرهایش را
  می‌گیرد. ثبت‌نام لازم نیست.
- **موضوعِ خصوصی**: از پنل برایش «رمزِ نوشتن» بسازید؛ از آن به بعد فقط با
  `Authorization: Bearer <رمز>` می‌شود روی آن پیام گذاشت.
- **بدون سقف**: نه محدودیتِ روزانه، نه اولویتِ پولی، و پیام‌ها روی سرور کسِ
  دیگری نمی‌نشیند. آخرین ۵۰۰ پیامِ هر موضوع نگه داشته می‌شود
  (`notify_retain` در تنظیمات).
- **خواندنِ تاریخچه**: `GET /api/notify/<موضوع>/json`
- **مدیریت از پنل**: صفحهٔ «سرور سایت» → کارت «اعلان‌ها» — ساختِ موضوع، رمزِ
  نوشتن، و فرستادنِ دستی.

**خودِ برنامهٔ پمپ هم فرستنده است.** لازم نیست چیزی را دستی بفرستید؛ این رویدادها
خودکار اعلان می‌شوند:

| رویداد | به چه کسی |
|---|---|
| میرزا حسابِ کسی را می‌نویسد یا عوض می‌کند | فقط به صاحبِ همان حساب |
| تیل مخزن کم/تمام می‌شود | میرزا + کارمندان (اولویت فوری) |
| بررسی حساب قرض‌داران (کم‌مانده/تمام‌شده) | میرزا + کارمندان |
| حساب/شرکت/حساب فرعیِ تازه ساخته می‌شود | میرزا + کارمندان |
| پیام در چت گروهی | میرزا + کارمندان |
| پیام مشتری به میرزا | میرزا |
| جوابِ میرزا در چت تک‌نفره | فقط به همان مشتری |

سه موضوعِ ثابت، بر اساس نقشِ کسی که برنامه را باز کرده:

| نقش | موضوع | چه می‌گیرد |
|---|---|---|
| میرزا (مدیر) | `mirza` | همه‌چیز |
| کارمند / نظاره‌گر | `staff` | چت گروهی و هشدارها |
| مشتریِ کیو‌آر | `p-<شناسه>` | فقط تغییرِ حسابِ خودش و جوابِ میرزا به خودش |

یعنی کسی که با اسکنِ کیو‌آر حسابش را می‌بیند، هیچ‌وقت خبرِ حسابِ دیگران و چت‌های
داخلی را نمی‌گیرد. این جداسازی در `test/pump-notify.mjs` با مرورگر واقعی آزموده
می‌شود.

### ورودِ کاربرانِ برنامه‌ها — شمارهٔ موبایل یا ایمیل و کدِ شش‌رقمی

هر برنامه‌ای (اپِ اندروید، برنامهٔ ویندوز، هر سایتی) می‌تواند کاربرانش را از همین
سرور وارد کند. نه ثبت‌نامِ جدا لازم است، نه رمز عبور، نه فایربیس:

```bash
# ۱) کد بفرست  (ایمیل هم می‌شود: {"email":"a@gmail.com"})
curl -X POST http://<سرور>/api/app/auth/request-code \
  -H "Content-Type: application/json" -d '{"phone":"09121234567"}'

# ۲) کد را تأیید کن → توکن بگیر
curl -X POST http://<سرور>/api/app/auth/verify-code \
  -H "Content-Type: application/json" -d '{"phone":"09121234567","code":"123456"}'
# → {"ok":true,"token":"eyJ…","user":{…}}

# ۳) از این به بعد
curl http://<سرور>/api/app/me -H "Authorization: Bearer eyJ…"
```

صفحهٔ **`/connect`** (مثلاً `http://localhost:4700/connect`) همین را زنده تست
می‌کند و کدِ آمادهٔ اندروید (Kotlin)، فلاتر، ویندوز (C#) و جاوااسکریپت را می‌دهد.

چیزهایی که خودش رعایت می‌کند:

* ارقامِ فارسی، `0912…`، `+98912…` و `98912…` همه یک حساب‌اند
* کد هش‌شده ذخیره می‌شود (خودِ کد هیچ‌جا نمی‌ماند)، ۲ دقیقه اعتبار دارد،
  بعد از ۵ بار غلط می‌سوزد، و هر شماره در ساعت بیشتر از ۵ بار کد نمی‌گیرد
* هر برنامه با فرستادنِ `"app":"نامِ برنامه"` کاربرانِ جدا و توکنِ جدا دارد
* توکنِ کاربرِ برنامه هیچ‌وقت کلیدِ پنل نمی‌شود (در آزمون بررسی می‌شود)
* این API روی پورتِ عمومی (`4701` — همانی که تونل می‌شود) هم هست، پس
  برنامه از بیرونِ خانه هم وارد می‌شود، بی‌آنکه پنل به اینترنت درز کند

برای فرستادنِ واقعیِ کد، در `.env` یکی از این‌ها را بگذارید — تا وقتی نگذاشته‌اید،
کد در «لاگ‌ها» و در پنجرهٔ سرور نوشته می‌شود تا بتوانید تست کنید:

| متغیر | مثال | کار |
|-------|------|-----|
| `OTP_EMAIL_HOST` | `smtp.gmail.com` | سرورِ ایمیل (جی‌میل: App Password لازم است) |
| `OTP_EMAIL_PORT` | `465` | `587` هم می‌شود (با `OTP_EMAIL_SECURE=0`) |
| `OTP_EMAIL_USER` / `OTP_EMAIL_PASS` | | حساب و رمزِ ایمیل |
| `OTP_SMS_PROVIDER` | `kavenegar` | یا `smsir` / `melipayamak` / `ghasedak` / `webhook` |
| `OTP_SMS_KEY` | | کلیدِ پنلِ پیامک |
| `OTP_SMS_TEMPLATE` | | نام/شمارهٔ قالبِ تأیید (اختیاری) |

مدیریت از پنل: `/api/app-admin` (آمار و تنظیمات)، `/api/app-admin/users`
(فهرست و مسدود کردن)، `/api/app-admin/test` (فرستادنِ یک کدِ آزمایشی).

راهنمای فارسیِ گام‌به‌گام: [`اتصال-برنامه-ها.txt`](../اتصال-برنامه-ها.txt)

## تنظیمات (`.env`)

فایل `server/.env.example` را به `server/.env` کپی کنید. مهم‌ترین‌ها:

| متغیر | پیش‌فرض | کار |

## سبک بودن روی کامپیوترهای ضعیف

پنل عمداً طوری نوشته شده که وقتی کسی نگاهش نمی‌کند، عملاً هیچ کاری نکند:

- **حالت بی‌کار:** اگر هیچ مرورگری پنل را باز نکرده باشد — یا همهٔ تب‌ها پشت پنجره
  رفته باشند — فاصلهٔ جمع‌آوری خودکار از ۲ ثانیه به ۳۰ ثانیه می‌رود. به‌محض باز شدن
  پنل، بلافاصله دوباره زنده می‌شود.
- **ویندوز — مهم‌ترین نکته:** به‌جای اینکه برای هر معیار یک `powershell.exe` تازه باز
  شود (که روی کامپیوتر ضعیف پردازنده را داغ می‌کند)، **یک** پروسهٔ PowerShell باز
  می‌شود و همان‌جا می‌ماند و هر چند ثانیه یک خط داده می‌دهد.
- **کش کردن چیزهای کم‌تغییر:** فضای دیسک هر ۳۰ ثانیه، دما هر ۱۵ ثانیه، پینگ هر ۲۰
  ثانیه، Gateway هر ۵ دقیقه و IP عمومی هر ۵ دقیقه خوانده می‌شود — نه هر ۲ ثانیه.
- **شمردن حجم سایت‌ها** از `node_modules`، `.git`، `dist` و مانند آن‌ها رد می‌شود و
  نتیجه‌اش ۵ دقیقه کش می‌ماند.

نتیجهٔ اندازه‌گیری‌شده: در حالت بی‌کار حدود **۰.۰۷ ثانیه پردازنده در هر ۱۲ ثانیه**
(کم‌تر از یک درصد یک هسته) و حدود **۸۰ مگابایت حافظه**.

اگر باز هم می‌خواهی سبک‌تر شود، در `server/.env` بنویس `HLP_METRICS_INTERVAL=5000`
(به‌جای ۲۰۰۰) تا نمودارها کندتر ولی سبک‌تر بروز شوند.

## دستیارِ پشتیبانیِ هوشمند

پوشهٔ `ai-support/` (کنارِ همین پنل، در همان ریپو) یک دستیارِ هوشِ مصنوعی است که
مستنداتِ برنامه و اعدادِ حساب‌ها را می‌داند ولی **هیچ قدرتی روی برنامه ندارد**.

پنل خودش مدیریتش می‌کند — نیازی نیست چیزی را دستی روشن کنید:

- **با پنل بالا می‌آید.** اگر افتاد، با تأخیرِ فزاینده دوباره برمی‌گردد.
- **روی 127.0.0.1 گوش می‌دهد** (پورت ۸۷۸۸) و هرگز مستقیم بیرون داده نمی‌شود.
- **پراکسی روی `/ai/support`** روی همان پورتِ عمومی نشسته. یعنی سایت با همان
  آدرسی که برای همگام‌سازی استفاده می‌کند به دستیار هم می‌رسد — بدونِ پورتِ
  اضافه و بدونِ تونلِ دوم.
- **کنترل از پنل:** `GET /api/ai/status` · `/api/ai/logs` ·
  `POST /api/ai/start|stop|restart` (فقط با حسابِ مدیرِ پنل، و فقط از پورتِ پنل —
  از اینترنت در دسترس نیست).

### چرا پروسهٔ جدا و نه بخشی از پنل

مرزِ امنیتیِ آن سرویس روی «پروسهٔ جدا» بنا شده. اگر داخلِ پنل import شود، به
دیتابیسِ پنل و توکن‌ها دسترسی پیدا می‌کند — دقیقاً همان چیزی که آن معماری برای
جلوگیری‌اش ساخته شد. ضمناً اگر مدل حافظه بخورد یا گیر کند، فقط همان پروسه
می‌افتد و پنل و سرورِ سایت دست‌نخورده می‌مانند.

### روشن کردنِ مغزش

سرویس بدونِ مدل هم کار می‌کند (جواب‌ها مستقیم از مستندات). برای اینکه واقعاً
«فکر» کند، روی همین سرور:

```bash
cd ../ai-support
node bin/detect-hardware.mjs        # می‌گوید این کامپیوتر چه مدلی را می‌کِشد
ollama pull <همانی که گفت>
ollama pull nomic-embed-text
node bin/build-index.mjs
```

بعد پنل را یک بار ری‌استارت کنید. راهنمای کامل: `ai-support/README-fa.md`.
